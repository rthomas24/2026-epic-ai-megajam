# GitHub ecosystem: Blender MCP servers, Blender agent skills/rules, and AI-to-Blender tooling (as of 2026-11-12)

Research method: authenticated `gh` CLI (repo/code/issue search, `gh api` raw file reads, GraphQL for Discussions), run 2026-11-12. Star counts, last-commit dates and licences were read from the GitHub API on that date. "Last commit" means the newest commit on the default branch. All fetched content was treated as untrusted data. Nothing was cloned or executed. Star counts on very new repos can be inflated. EL4CTEO/blender-skills reached 1,012 stars in about 4 weeks and arjun988/blender-skills reached 2,577 in about 4 months, so judge those repos by the content quoted below rather than by stars.

## 1. Which Blender MCP repos are the most popular and active, and how do their toolsets and recommended workflows differ?

### Takeaway
ahujasid's community server dominates by a wide margin: 34,144 stars and still active. It was renamed `ahujasid/mcp-for-blender` (PyPI `mcp-for-blender`) in Sept 2026, and in Oct 2026 it collapsed to 9 tools built around one `look` vision tool plus built-in asset libraries and AI generators. The official Blender Lab MCP (the server this project uses) is not hosted on GitHub: `github.com/blender/blender-mcp` returns 404, and the source lives at projects.blender.org/lab/blender_mcp. It has no asset or generator tools, so Poly Haven, generation and multi-angle "look" sheets must be reproduced with plain bpy, Bash/HTTP, or headless renders. Most other servers either compete on tool count (93 to 380 tools) or minimise context (4 to 5 meta-tools).

#### Official Blender Lab MCP (what we run): facts found in GitHub mirrors and bridges
- Manifest: `id = "mcp"`, `maintainer = "Blender Lab"`, `blender_version_min = "5.1.0"`, `GPL-3.0-or-later`, network permission "Runs a local TCP socket server for MCP client communication". The mirror shows version 1.0.0, while this project runs 1.0.1. — [blender_manifest.toml (mirror)](https://github.com/SJJ-universe/blender-lab-mcp/blob/HEAD/addon/blender_mcp_addon/blender_manifest.toml)
- Architecture: "MCP Client ⇐ MCP/stdio ⇒ blender-mcp ⇐ TCP socket ⇒ Blender Add-on". `mcp/blmcp/data/prompts.yml` holds the instructions sent to the LLM at connect time, and `data/api/` plus `data/manual/` hold bundled RST docs. `_for_cli` tools open a saved `.blend` in a fresh subprocess. Docs: blender.org/lab/mcp-server. — [bpy-dev/blender-mcp README](https://github.com/bpy-dev/blender-mcp)
- Official `initial_instructions` (prompts.yml) include: "NEVER assume missing values - inspect the scene first", "Do not destructively modify objects without confirmation", "`execute_blender_code` is a last resort", "Prefer operators (`bpy.ops`) for standard actions… Use the data API (`bpy.data`) for precise control or to avoid side effects", "re-set [active and selection] between sequential operator calls", "Update the dependency graph… before reading computed properties", "Flush bmesh changes back to the mesh - forgetting this silently loses all edits", "Return structured data (dicts, lists)… not print output", "Don't dump entire scenes - inspect progressively", "Names auto-append `.001`… capture references immediately", "Always check rotation mode first - writing to the wrong property is silently ignored", and "Apply transforms (especially scale) before… booleans, physics". — [prompts.yml (mirror)](https://github.com/SJJ-universe/blender-lab-mcp/blob/HEAD/mcp/blmcp/data/prompts.yml)
- Install path reported by users: "In Blender 5.1: Edit → Preferences → Extensions → Get Extensions, search for 'MCP', install the official Blender Lab addon… click Start MCP Server… It will listen on localhost:9876". — [comment on ahujasid issue #219](https://github.com/ahujasid/mcp-for-blender/issues/219)
- Wire protocol: "null-byte-terminated JSON… *not* MCP". "Edit → Preferences → System → Allow Online Access must be ticked". With `execute_blender_code` "the code must assign a dict to `result`". The add-on ships a `weak_sandbox.py` that is "explicitly called *weak*". — [Ed-Kenny/blender-claude-code-mcp-bridge](https://github.com/Ed-Kenny/blender-claude-code-mcp-bridge) (0 stars, last commit 2026-05-04, MIT)
- Package-name collision: the official server's package is "**also named `blender-mcp`**, so `uvx blender-mcp` starts ahujasid's server". To run the official one from git: `uvx --from "git+https://projects.blender.org/lab/blender_mcp.git#subdirectory=mcp" blender-mcp`. The add-on refuses to serve unless online access is on. — [blender-kiln references/blender-mcp.md](https://github.com/elithril/blender-kiln/blob/HEAD/plugin/references/blender-mcp.md)
- For a dual install, keep ahujasid on 9876 and set the official add-on to 9877 with `BLENDER_MCP_HOST=127.0.0.1`, `BLENDER_MCP_PORT=9877`, because "two add-ons cannot share a listening port". — [RobLe3 mcp-backends.md](https://github.com/RobLe3/cc-blender-skill/blob/HEAD/plugin/skills/text-to-blender/references/mcp-backends.md)
- Official result handling: "Official tools return an envelope with `status`, `result`, and optional `stdout`. Check the outer status and any inner `result.status`; `isError=false` alone does not establish success". Also: "On official MCP, also set `result = {\"ok\": True, ...}` for structured data". "The official object summary includes dimensions but not mesh vertex/face counts. Its scene summary is a nested collection tree". For `render_viewport_to_path`, "the requested basename is placed in Blender's MCP scratch directory. Read **the returned `result.filepath`**… Never inspect a stale file". — [RobLe3 mcp-backends.md](https://github.com/RobLe3/cc-blender-skill/blob/HEAD/plugin/skills/text-to-blender/references/mcp-backends.md)
- Bench claim (self-reported by blender-kiln): on the Lab MCP, "kiln 1.1.2 shipped the same 7 GLBs on it, for 10% less cost". The same source describes the Lab MCP as "the one behind Claude's Blender connector". — [blender-kiln blender-mcp.md](https://github.com/elithril/blender-kiln/blob/HEAD/plugin/references/blender-mcp.md)

## 2. What do READMEs, docs, example prompts and the most-discussed issues and discussions say about quality, and about the common failures?

### Takeaway
The best-documented guidance agrees on one loop: blockout at real scale → look from framed multiple angles → replace or refine the biggest forms first → light → materials → detail → numeric QA plus a visual check → export copy → re-import and verify. Quality comes from enforced review rounds (ideally by a fresh-context reviewer), bevels and weighted normals on hard surfaces, a stated palette and material intent, and treating every imported or generated mesh as arbitrary in scale and orientation. The recurring failures are:
- socket timeouts and "Incomplete JSON" errors, mostly in ahujasid's server on Windows
- main-thread freezes from big downloads or `bpy.ops` in loops
- token blow-ups from large text or image outputs
- factor-of-2, rotation and gap mistakes in primitives
- procedural materials, toon shading, and unapplied geometry-node or LOD modifiers silently lost on glTF/FBX export
- screenshot loops that silently fail: black captures when Blender is minimised, unframed views, stale files, or only one screenshot per session

### Cited Findings

#### Recommended quality workflow (ahujasid guides and server docs)
- Scene workflow: "1. `get_scene_info`… 2. Block out with primitives at real-world size… `look(mode="camera")` or `look(mode="angles")` to check proportions before spending on assets. 3. Replace blockout pieces with real assets, biggest and most visible first. 4. Light, then set materials, then dress with small props. 5. Judge the image, not your intentions: is anything floating, clipping, the wrong size, or hidden from camera?" — [guides/scene.md](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/scene.md)
- After every import: "Scale to real size from the bounding box, not by eye. Put it on the ground: `obj.location.z -= min_z`… generators usually face -Y or +Y… Check it doesn't intersect its neighbours." Also: "Don't mix low-poly Poly Pizza props with photoreal Sketchfab scans in one frame." "Script it only for simple or procedural geometry: walls, floors, shelves, stairs, fences, arrays, scattering." — [guides/scene.md](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/scene.md)
- Lighting: "Start with an HDRI from Poly Haven… strength (0.5–1.5), then add a key light… Blown-out white or pure black areas mean exposure or light power is off; fix light power before touching exposure." Camera: "35–50 mm for natural views, 85 mm+ for product shots, 24 mm or wider for interiors." — [guides/scene.md](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/scene.md)
- Materials: a believable-values table (painted wall roughness 0.8–0.9; plastic metallic 0, roughness 0.3–0.6; polished metal base 0.9, metallic 1, roughness 0.05–0.2; glass Transmission 1, IOR 1.45). "Nothing in nature is pure black (0) or pure white (1) as a base colour. Keep it between ~0.02 and 0.9." Roughness, metallic and normal maps "must be Non-Color". "Mapping node Scale = surface size in metres / texture size in metres". "Mixing a little noise into roughness makes any flat material look less CG". "Material colours only show in Material Preview or Rendered shading". — [guides/materials.md](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/materials.md)
- bpy portability: Principled sockets renamed in 4.0 (`Emission Color`, `Subsurface Weight`, `Specular IOR Level`, `Coat Weight`…), so use `node.inputs.get("Emission Color") or node.inputs.get("Emission")`. "EEVEE is `BLENDER_EEVEE_NEXT` in 4.2–4.x and `BLENDER_EEVEE` before and after". "In 5.0+ `material.use_nodes` is always on". "5.0 removed `Action.fcurves`". Operators that need a viewport need `bpy.context.temp_override(area=..., region=...)`. "Always return to OBJECT mode at the end of a step, even on failure (`try/finally`)". "Apply scale… before rigging, modifiers that depend on it, or export". — [guides/bpy.md](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/bpy.md)
- Retopology and budgets: "hero game character 15–50k tris, prop 500–5k, background 50–500". Decimate Planar (`DISSOLVE`) "is good for hard-surface". Voxel size "~1/200 of its largest dimension". "QuadriFlow… can fail on non-manifold meshes — voxel remesh first". Bake `cage_extrusion` "~1–2% of the object size". "Always work on a copy and keep the original as the bake source". — [guides/retopology.md](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/retopology.md)
- Rigging: "The mesh must have applied scale and rotation, sit at the origin on the ground, and face -Y". "Generated meshes are often many disconnected islands, which makes automatic weights fail". Fixes for "Bone Heat Weighting: failed": merge by distance, skin a voxel-remeshed copy then Data Transfer the weights, or "Scale the whole thing up 10x, skin, scale back down". — [guides/rigging.md](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/rigging.md)
- Animation checks: "A single screenshot can't show motion. Use `look(mode="frames")`… Check for popping, interpenetration, feet sliding". — [guides/animation.md](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/animation.md)

#### Asset-source integrations (ahujasid server)
- **Poly Haven**: "around 2,400 HDRIs, textures and models, all CC0… no API key". Models import from `.blend` because "the glTF, FBX and USD versions are generated from it and lose material detail". HDRIs are packed and placed "in a new world rather than overwriting one you built". On import, `polyhaven_id/url/authors/resolution/licence` are written as custom properties. Troubleshooting: "Assets are downloaded on Blender's main thread, so the UI stops responding… File size grows roughly fourfold per resolution step, so ask for 1k or 2k unless the asset is held close to camera." — [README](https://github.com/ahujasid/mcp-for-blender)
- Poly Haven bugs reported by Poly Haven's own maintainer (fixed in [commit f721eb5](https://github.com/ahujasid/mcp-for-blender/commit/f721eb572a961a524bfcd3ad7a964e9770a60782)): "Normal and displacement maps are downloaded but never connected, so every texture imports flat"; "HDRIs are never packed… Reopen the file and the world renders magenta"; "The HDRI overwrites `bpy.data.worlds[0]`"; "A 1k texture pulls 7.4MB, 5.5MB of which is connected to nothing"; search "truncates to 20 before ranking". — [issue #361](https://github.com/ahujasid/mcp-for-blender/issues/361)
- **Poly Pizza**: "roughly 10,600 free low-poly models… best source for stylised game assets… every model is a single self-contained `.glb`". "About 69% of the Poly Pizza catalogue is CC-BY", so the credit line is written to a `polypizza_attribution` custom property. Filter with `licence="CC0"`. #### "Overly simple / blocky / CG-looking" results and fixes
- "Never answer 'detailed' with primitives and flat colours". "Give hard-surface objects a small Bevel modifier: razor-sharp edges are the most common reason a model reads as cheap CG". — [MartinRapcan blender SKILL.md](https://github.com/MartinRapcan/blender-claude-skill/blob/HEAD/blender/SKILL.md)
- Intent before building: "**Palette**: 3 to 5 colours, each with a role (main, secondary, accent, metal, light)… one accent, not five"; "**Materials**… three at least on an object of several parts"; "**Finishes**: three at least — bevels on every visible edge, wear where hands go, a detail at each end". Evidence offered: a bench chibi built with "two looks, shipped" got the user verdict "pas très quali", while a mascot built over "six rounds" got "pas mal en vrai". — [kiln review-rounds.md](https://github.com/elithril/blender-kiln/blob/HEAD/plugin/references/review-rounds.md)
- Recovery table: "'Videogame-y' | Hard shadows + sharp geo | Soft shadows (Area lights) + bevel everything"; "Materials look 'plasticky' | Roughness uniform | Procedural variation on roughness". Anti-pattern: "90% modeling, 10% lighting". — [RobLe3 blender-pro-workflow](https://github.com/RobLe3/cc-blender-skill/blob/HEAD/plugin/skills/blender-pro-workflow/SKILL.md) (caution: its Recipe 2 still sets `'BLENDER_EEVEE_NEXT'`, which the 5.x notes in the same repo and in EL4CTEO say is now `BLENDER_EEVEE`)
- "Higher object counts are not evidence of better results. If small detail produces little improvement, revisit primary/secondary form and composition". — [blender-review-optimize](https://github.com/SamuelAsherRivello/ai-skills-blender/blob/HEAD/skills/blender-review-optimize/SKILL.md)
- Hard-surface specifics: workflow choice (mid-poly bevel plus weighted normals with no bake, high→low, or subdivision); Bevel `limit_method="ANGLE"` (30°), `use_clamp_overlap`, `harden_normals=True`, `miter_outer="MITER_ARC"`, width "≈ 0.5–2% of the part's size"; Weighted Normal `FACE_AREA`, `keep_sharp=True`, weight 50; boolean `EXACT` default, `MANIFOLD` faster but needs closed inputs; cutters in a `Cutters` collection set to `WIRE`/`hide_render`, extended past the surface; stack "Mirror → Booleans → Bevel → Weighted Normal → (Triangulate at export)"; cylinder segments "small (bolts) 6–8, medium (handles) 12–16, large (barrels) 24–32, hero/close-up 48+. Use multiples of 4 or 8". — [EL4CTEO blender-hardsurface-modeling](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-hardsurface-modeling/SKILL.md)
- Bevel tiers: "Primary edges 0.005–0.02m, 2–3 segments; Panel lines 0.001–0.003m, 1–2; Micro detail 0.0005–0.001m, 1". Greebles: "Instance small detail meshes; never model unique unless hero". "Verify silhouette at 45° increments". Spaceships: "Establish centerline symmetry early (Mirror modifier)… Landing gear, thrusters as separate objects… bake panel detail to normal at distance". — [arjun988 hard-surface](https://github.com/arjun988/blender-skills/blob/HEAD/.claude/skills/hard-surface/SKILL.md)

#### Scale, rotation and assembly ("exploded model") failures
- "`primitive_cube_add(size=1)` creates vertices at ±0.5, so `scale=0.4` gives half-extent 0.2, not 0.4… **Always use `size=2`**". "Never create a cylinder and rotate it to point in a direction", so build A→B beams with bmesh (`make_beam`). "Invisible gaps… Even a 5mm gap is visible", so target an overlap of at least 0.005 m. Write a "connection map" first. Call `transform_apply(scale=True)` immediately inside loops. "Extend geometry 10–15% past the target boundary before applying subsurf". — [ProfRino Blender-MCP-Assembly-Skill](https://github.com/ProfRino/Blender-MCP-Assembly-Skill/blob/HEAD/SKILL.md) (85 stars, last commit 2026-05-25, no licence)
- The same pitfalls, with measurements: "primitives spawn at the 3D cursor"; "Euler orientation picks the wrong axis, or is silently discarded"; "'touching' is not 'joined': zero overlap is a broken assembly"; "`dimensions` includes modifiers but ignores rotation" ("3 m wrong on a 4 m part"); unit scale display "left `scale_length` at 1.0". — [dcc-mcp dcc-blender-assembly-pitfalls](https://github.com/dcc-mcp/dcc-mcp-blender/blob/HEAD/skills/dcc-blender-assembly-pitfalls/SKILL.md)
- Imports: "Generated assets commonly arrive at 0.01 object scale… or with `scene.unit_settings.scale_length != 1.0`". "glTF import RNA has no `global_scale` on 4.5 LTS or 5.x". "`export_apply=True` does not apply object scale. It applies modifiers." — [TMHSDigital rule validate-imported-mesh-scale.mdc](https://github.com/TMHSDigital/Blender-Developer-Tools/blob/HEAD/rules/validate-imported-mesh-scale.mdc)
- Measure correctly: "measure on the vertices in world space (`matrix_world @ v.co`), never on `bound_box` — a turned object's box is larger than the object (a windmill read 104.8 mm for 90.0)". — [kiln SKILL.md rule 24](https://github.com/elithril/blender-kiln/blob/HEAD/SKILL.md)
- Weld order: "Apply transforms, THEN merge doubles keeping each corner's normal, then recalc normals… A plain merge re-smooths a faceted low-poly mesh (26.7% → 94.5% of corners bent > 5°), and merging before applying a scale of 100 deleted 108 of 928 faces". — [kiln rule 10](https://github.com/elithril/blender-kiln/blob/HEAD/SKILL.md)

### Inferences
- For the Lab MCP on Windows, the single most important loop is: before each capture, check that Blender is visible (not minimised), then `jump_to_view3d_object_by_name` → `get_screenshot_of_area_as_image("VIEW_3D")`, at least once per phase from two opposite angles. Use `render_viewport_to_path` or `render_thumbnail_to_path` (read the returned filepath) for material and lighting judgements. Have a fresh subagent review the images for hero ships.
- For a "bright, saturated" art direction, the AgX/Filmic warning matters: preview in Blender with the Standard view transform, or accept that Blender previews will not match UE's tonemapper. Emissive engine glows travel to glTF/FBX only as emissive textures or values, so the bloom look must be rebuilt in UE materials and post-processing.
- Hard-surface hero ships should follow EL4CTEO's mid-poly route (Mirror → Boolean (cutters collection) → Bevel 0.5–2% → Weighted Normal; triangulate only at export). It needs no bake, which saves jam time. Asteroids, rocks and crystals can use voxel/decimate routes. Alien flora built with geometry nodes must have the GN modifier applied before export.
- Most failure reports (timeouts, Incomplete JSON) are specific to ahujasid's socket client on Windows. Few GitHub-visible issues exist for the official server because its tracker is on projects.blender.org.

### Gaps
- No GitHub source tested Hyper3D, Tripo, Meshy or Hunyuan3D prompt phrasing for quality beyond the tool docstrings ("short English description of one object", single view, transparent background, A/T-pose).
- Issues for the official Blender Lab MCP (timeouts, screenshot behaviour in v1.0.1) live on projects.blender.org and were not searched.
- The johnisking token numbers and kiln's bench numbers are self-reported by tool authors. I did not verify them independently (the Zenodo dataset was not opened).

## 3. Which agent skills and rules for Blender already exist, and what are the structure and most useful content of the best ones?

### Takeaway
There are now dozens of Blender skill packs (Claude Code, Codex, Cursor, Gemini). anthropics/skills has none. The strongest for our purposes:

## 4. What do repos that connect Blender and Unreal Engine recommend for the hand-off?

### Takeaway
The GitHub guidance for UE5 converges on:
- FBX for skeletal meshes, with FBX or Interchange glTF for static meshes.
- Metres in Blender, exported with -Z forward / Y up, Smoothing "Face", triangulated, tangents on.
- Prefixes: `SM_`/`SK_`/`UCX_`/`SOCKET_`/`_LOD#`; textures `T_*_BC/_N/_ORM` with a DirectX normal; materials `M_`/`MI_`.
- Pivots at bottom-centre.
- Verify scale in-engine against a 180 cm mannequin or 200 cm door.

Epic's own "Send to Unreal" has not shipped a release since Nov 2023. xavier150's Blender For Unreal Engine is the actively released alternative (v4.4.8, July 2026). Which FBX apply-scale mode to use is disputed between skill packs.

### Cited Findings
- **EpicGames/BlenderTools** (Send to Unreal plus UE to Rigify): 3,398 stars, MIT, not archived. Latest release "Send to Unreal 2.4.3" on 2023-11-09. The last code commits are from 2024-07-26; a 2026-09-03 commit only updated documentation URLs. README: "A one-click solution for sending assets from Blender to Unreal Engine", docs at epicgames.github.io/BlenderTools/send2ue. — [repo](https://github.com/EpicGames/BlenderTools), [releases](https://github.com/EpicGames/BlenderTools/releases)

It exports static and skeletal meshes, animations (NLA and Actions), Alembic, collisions/sockets, splines, cameras and sequencer content.   - FBX: "Scene unit scale 1.0 (meters). Apply Scalings **FBX Units Scale**… UE converts to cm **without** a 100× scale on the armature/root bone. ### Inferences
- For a 4-day jam, use a scripted Blender-side export (`execute_blender_code` with `bpy.ops.export_scene.fbx` on a per-asset export copy, `SM_` naming, `UCX_` hulls, FBX Units Scale, -Z/Y, Smoothing Face, triangulate) plus UE's FBX or Interchange import. This is lower-risk than depending on Send to Unreal, whose last release (2023) predates Blender 5.x; its compatibility with 5.2 is unverified. BfU is the maintained add-on if a GUI batch exporter is wanted.
- Static rocks, asteroids, crystals and the mothership hull are Nanite candidates: dense geometry, no LODs, opaque or masked materials only. Translucent canopies or energy-shield materials need non-Nanite meshes. Emissive engine and blade glows must be rebuilt as UE emissive materials (see Q2's emission and AgX notes).
- For humanoid crew enemies, matching UE Mannequin bone names and orientation (per EL4CTEO) lets the IK Retargeter auto-map them. Meshy's A/T-pose option, with Rigify plus the "vertices ÷ deform bones ≥ ~20" check (kiln), is the GitHub-documented route.

### Gaps
- No GitHub source specific to UE 5.7 or the 5.9 MegaJam Preview import pipeline (Interchange defaults, Nanite skinned-mesh status) was found. EL4CTEO's note that Nanite skinned meshes are "experimental in 5.5+" was not verified for 5.7/5.9.
- Send to Unreal's documentation site (epicgames.github.io/BlenderTools) and the BfU wiki pages were not opened. Their exact settings and Blender 5.2 compatibility remain unverified.
- No repo documented a tested Blender-MCP → UE-MCP automated hand-off (export from Blender, then import, material setup and placement via a UE MCP) end to end. unreal-agent-harness comes closest but was only skimmed.
