# Performance log, Nov 14 2026 (Teammate 7, issue #89)

Ryan's goal: as fast as possible, with no lag. Targets:
- 60 fps everywhere;
- no frame over 33 ms in combat;
- no hitch over 100 ms outside a loading screen.

## How each run is measured

- **Build:** a packaged Development build (console and CSV profiler available), 1920x1080 windowed. One game instance;
  the count of other rendering Unreal instances is recorded for every run.
- **Audio:** the real output device, muted with `au.MuteAudio 1`, so mixer underruns can occur as they would for a player.
  `LogAudioMixer` is at Verbose, `LogAudioMixerDebug` at Log, and `au.MinLogTimeBetweenUnderrunWarnings` is 0.
- **Profile:** `csvprofile` covers the whole run. Each phase starts at the `TD.Stage` / `TD.Travel` / input command that
  begins it (the CSV event).
- **Scripts:**
  - Driver: `perf-run.ps1`, in T7's session scratchpad, not committed. It passes timed `-TDExecAt` commands.
  - Summary: `csvphase.py`, also not committed. Per phase it reports frame / game / render / GPU ms; >33 ms and >100 ms
    frame counts; draw calls and triangles; VRAM; RAM; GC count. It also lists the worst 25 frames with their top
    game-thread scopes and CSV events (FlushAsyncLoading, GC, PSO), and every underrun with the worst frame in the 0.5 s
    before it.
- **Hitch causes:**
  - FlushAsyncLoading: a synchronous load.
  - GC: garbage collection.
  - A PSO event: pipeline compile.
  - Large game / render thread scopes.
  - All threads idle: the process was not scheduled, i.e. machine contention, not the game.

## The two in-play hitches from baseline 1, traced

- **Wave 3 start, 473 ms: not a wave-start cost.** The frame is the `TD.Stage Wave3` console command's own work. The
  journey jump restarts the run and respawns, on the game thread, inside the command, so no stat scope covers it. The
  frame before it holds the command and four FlushAsyncLoading events. A natural wave 3 start does not run this code.
  The natural run measures the real wave start; T4 should not chase this one from this data.
- **Verdance arrival, 714 ms: the stage cheat's direct `LoadMap`.** Galaxy to L_Planet_Verdance with no cover:
  `LoadMap` took 0.44 s, then 85 MB was read in one frame, plus FlushAsyncLoading 47 ms and two new PSOs. In natural
  play, entry travels behind ENG-38's white cover. The real entry in baseline 1 (`TD.Travel.ToPlanet`, flown into the
  atmosphere) peaked at 94 ms. Scatter AddInstances was only 5 ms in this frame. If the scatter apply's 109-330 ms comes
  from T4's own probe, it is not in this CSV; the natural run N measures it after the cover drops.
