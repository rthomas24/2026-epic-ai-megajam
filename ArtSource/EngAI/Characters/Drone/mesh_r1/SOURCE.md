**GLB (`SM_NullDrone.glb`).** Vertex values are in **centimetres**, with `export_yup=false`, so the
file itself is +Z up / +X forward rather than glTF's default +Y up / +Z forward. glTF's official unit
is the metre: if an importer assumes metres, set uniform scale to **0.01**; if it treats the numbers as
cm (or you are in Unreal and want 90 uu), use scale **1.0**. The GLB embeds the OpenGL (glTF)
normal, plus BC, metallic-roughness and emissive.

**FBX (`SM_NullDrone.fbx`).** Exported with the repo's Unreal convention (`apply_unit_scale=True`,
`apply_scale_options='FBX_SCALE_UNITS'`, `axis_forward='-Z'`, `axis_up='Y'`, face smoothing, tangents,
triangulated). The file's `UnitScaleFactor` / `OriginalUnitScaleFactor` are **100** (centimetres).
Import with the usual Interchange pipeline, uniform scale 1.0; it should measure 90 cm across in Unreal.

## Normal convention

`source/texture_normal.png` (and the normal embedded in both the raw and the derived GLB) is
**OpenGL** (Y+): it is the glTF normal, B-channel is nearly 255 (outward Z), and the glTF 2.0 spec
requires OpenGL tangent-space normals. That matches how Rodin ships a glTF pack.

For Unreal, which expects **DirectX** (Y−), the delivery map `T_NullDrone_N.png` has the green
channel inverted (`G' = 1 - G`). Red and blue are unchanged. This is the same convention used for
the R-027 terrain sets. When importing the loose maps, set N as a Normalmap (DirectX) and do **not**
also use the GLB-embedded OpenGL normal.
