**FBX (`SM_NullCarrier.fbx`) — preferred for Unreal.** Exported with the repo's Unreal convention
(`apply_unit_scale=True`, `apply_scale_options='FBX_SCALE_UNITS'`, `axis_forward='-Z'`,
`axis_up='Y'`, face smoothing, tangents, triangulated). The file's `UnitScaleFactor` /
`OriginalUnitScaleFactor` are **100** (centimetres). Reimported in Blender it measures
46.000 × 22.764 × 17.852 m, centred on the origin. Import with the usual Interchange
pipeline, uniform scale **1.0**; it should measure the brief length in Unreal.

**GLB (`SM_NullCarrier.glb`).** Vertex values are in **centimetres**, with `export_yup=false`, so the
file itself is +Z up / +X forward rather than glTF's default +Y up / +Z forward. glTF's official unit
is the metre: if an importer assumes metres, set uniform scale to **0.01**; if it treats the numbers as
cm (or you are in Unreal and want the brief length in uu), use scale **1.0**. The GLB embeds the OpenGL (glTF)
normal, plus BC, metallic-roughness and emissive. Prefer the FBX for the engine import; Blender's default
glTF importer will swap Y/Z if it applies a second +Y-up conversion on top of `export_yup=false`.

## Lead-note check: red-orange seams and the white 'eye' bar

Checked on the 2K maps and on the derived-mesh renders (see `contact_sheet.png`).

- **Red-orange seams: present.** They read on the forward horns, the hull chevrons, the hangar-bay interiors, the tower and the outrigger pod rims, in both albedo and emissive. The emissive has about 47,200 orange pixels (1.13% of the 2K map). The hangar bays glow from the inside, as in the concept. The hull is a deep, slightly warm black (mean RGB about 36, 19, 16), so the seams have good contrast.
- **White eye: present.** The emissive has about 4,050 near-white pixels (0.097% of the map). On the mesh it reads as a lamp / eye between the horns and as small tower lights, in the same places as the concept.

## Notes and issues

- The silhouette is faithful: a horned capital with a pair of forward claws, a white eye between them, open side hangar bays, a mid-ship tower, and four outrigger engine pods. It clearly shares the Null / Triad family language as asked in R-034.
- The approved concept is followed closely. Small departures: the tower is a little shorter and less stepped than the concept; at 8,906 tris some hangar interior and plating detail is softer than a 30–60k / 50k mesh would have been.
- **Flag — triangle count vs 50K Raw:** the pack exported 8,906 tris despite the 50K Raw setting. There is no 50k file in the download. Kept as shipped (under the 30–60k Nanite budget, and well under the ~20k decimate cutoff used for non-capital fleet craft). One 2K PBR set was shipped, not 2 × 2K.
- No rig, no sockets, no UCX collision — please add those on import if you want them. This drop was not run through `blender-ai-mesh-cleanup`.
- Topology is Rodin's auto-triangulation (not clean quads).
- A per-ship heat-glow mask matching these UVs is in `../heatmask_r1/`.

## Normal convention

`source/texture_normal.png` (and the normal embedded in both the raw and the derived GLB) is
**OpenGL** (Y+): it is the glTF normal, B-channel is nearly 255 (outward Z), and the glTF 2.0 spec
requires OpenGL tangent-space normals. That matches how Rodin ships a glTF pack.

For Unreal, which expects **DirectX** (Y−), the delivery map `T_T_NullCarrier_N.png` has the green
channel inverted (`G' = 1 - G`). Red and blue are unchanged. This is the same convention used for
the accepted Drone mesh_r1, the player-ship mesh_r1, the Warden mesh_r1 and the earlier Null fleet
meshes. When importing the loose maps, set N as a Normalmap (DirectX) and do **not** also use the
GLB-embedded OpenGL normal.
