(`apply_unit_scale=True`, `apply_scale_options='FBX_SCALE_UNITS'`, `axis_forward='-Z'`,
`axis_up='Y'`, face smoothing, tangents, triangulated). The file's `UnitScaleFactor` /
`OriginalUnitScaleFactor` are **100** (centimetres). Import with the usual Interchange pipeline,
uniform scale **1.0**; it should measure 550.0 cm long in Unreal.

**GLB (`SM_NullFighter.glb`).** Vertex values are in **centimetres**, with `export_yup=false`, so the
file itself is +Z up / +X forward rather than glTF's default +Y up / +Z forward. glTF's official unit
is the metre: if an importer assumes metres, set uniform scale to **0.01**; if it treats the numbers as
cm (or you are in Unreal and want 550 uu), use scale **1.0**. The GLB embeds the OpenGL (glTF)
normal, plus BC, metallic-roughness and emissive.

## Lead-note check: red-orange seams and the white 'eye' bar

Checked on the 2K maps and on the derived-mesh renders (see `contact_sheet.png`).

- **Red-orange seams: present.** They read on the inner edges of the crescent wings, the dorsal chevron and the engine rings, in both `texture_diffuse.png` / `T_NullFighter_BC.png` and `texture_emissive.png` / `T_NullFighter_E.png`. The emissive has about 9,900 orange pixels (0.24% of the 2K map) plus the engine-bell islands. They are clearly visible in the top and 3/4 contact-sheet views.
- **White 'eye' bar: present, slightly softened.** The emissive has about 19,500 near-white pixels (0.46% of the map). On the mesh it reads as a pale / white chevron highlight on the nose (the same place as the concept's horizontal eye bar) rather than a single hard-edged bar. It is most obvious in the top view and in the 3/4. In-engine, with the loose `T_NullFighter_E.png` as the emissive, it should hold up at the fighter's on-screen size; if the team wants a harder bar they can punch the emissive on that island.

## Notes and issues

- The silhouette is faithful: crescent scythe-wings, a pointed nose with chin guns, a dorsal spine chevron, rear engines.
- The approved concept has **two** rear engines. The Rodin mesh has **three** clustered nozzles. Worth a look; it does not break the silhouette and is probably fine at the size fighters are seen, but it is a departure.
- The hull is a mid-grey / silver rather than a deep black, so the seams have less contrast than the concept at some angles (the front contact-sheet view is the weakest). The emissive map still carries the orange and the white, so a slightly darker base-colour multiply in the material would bring it closer to the concept if wanted.
- No rig, no sockets, no UCX collision — please add those on import if you want them. This drop was not run through `blender-ai-mesh-cleanup`.
- Topology is Rodin's auto-triangulation (not clean quads). Tris are already inside the 6–10k cap.

## Normal convention

`source/texture_normal.png` (and the normal embedded in both the raw and the derived GLB) is
**OpenGL** (Y+): it is the glTF normal, B-channel is nearly 255 (outward Z), and the glTF 2.0 spec
requires OpenGL tangent-space normals. That matches how Rodin ships a glTF pack.

For Unreal, which expects **DirectX** (Y−), the delivery map `T_NullFighter_N.png` has the green
channel inverted (`G' = 1 - G`). Red and blue are unchanged. This is the same convention used for
the accepted Drone mesh_r1, the player-ship mesh_r1 and the Warden mesh_r1. When importing the
loose maps, set N as a Normalmap (DirectX) and do **not** also use the GLB-embedded OpenGL normal.
