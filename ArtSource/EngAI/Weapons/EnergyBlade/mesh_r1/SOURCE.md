## Derived delivery (what to import)

Reoriented, pivoted and scaled in Blender 4.5.3. Source files were not modified. For each
mesh the grip-wrap axis was fitted from mid-barrel cross-sections, then rotated to **+Z**
(pommel −Z, hinges / guard +Z) and yawed so the emissive strip (the blade / stowed rail)
sits on **+X**. The origin was set to the centre of the grip wrap — the same semantic
point on both meshes — so they can be swapped or toggled in `hand_r` and the hand stays
aligned. No decimate was applied.

Scale was set so both barrels measure **Ø 3.70 cm** (inside the 3.4–4.0 cm hand-fit
range). That puts the deployed tip-to-pommel at **39.7 cm**, on the 40–45 cm target.
Pommel-to-guard comes out longer than the 13–15 cm hand-scale note because of the mesh
proportions (large hinge crowns and a long wrap). Shrinking the hilt to 15 cm would thin
the barrel to about 2.3 cm, which would miss the hand-fit range, so the 3.70 cm barrel
was kept.

**FBX (`SM_EnergyBlade_Deployed.fbx`, `SM_EnergyBlade_Folded.fbx`) — preferred for Unreal.**
Exported with the repo's Unreal convention (`apply_unit_scale=True`,
`apply_scale_options='FBX_SCALE_UNITS'`, `axis_forward='-Z'`, `axis_up='Y'`, face
smoothing, tangents, triangulated). The files' `UnitScaleFactor` /
`OriginalUnitScaleFactor` are **100** (centimetres). Reimported in Blender, Deployed
measures 0.249 × 0.042 × 0.359 m and Folded 0.120 × 0.045 × 0.237 m, with the origin
at the grip-wrap centre (not the AABB centre). Import with the usual Interchange
pipeline, uniform scale **1.0**; they should measure the sizes above in Unreal.

**GLB (`SM_EnergyBlade_Deployed.glb`, `SM_EnergyBlade_Folded.glb`).** Vertex values are in
**centimetres**, with `export_yup=false`, so the file itself is +Z up / +X forward rather
than glTF's default +Y up / +Z forward. glTF's official unit is the metre: if an importer
assumes metres, set uniform scale to **0.01**; if it treats the numbers as cm (or you are
in Unreal and want the sizes in uu), use scale **1.0**. The GLB embeds the OpenGL (glTF)
normal, plus BC, metallic-roughness and the cleaned emissive. Prefer the FBX for the
engine import; Blender's default glTF importer will swap Y/Z if it applies a second +Y-up
conversion on top of `export_yup=false`.

## Emissive mask

The Lead asked for an emissive mask for the cyan edge strip (the game tints it), plus the
LED pips.

- **Deployed.** `source/deployed/texture_emissive.png` already isolated the strip and pips
  (bright cyan / white on the rail and pips, black elsewhere; about 3.1% of pixels lit).
  A very light chroma clean was applied; the delivery `T_EnergyBlade_Deployed_E.png` keeps
  the crisp strip and pips (about 2.9% lit) and does not change the look.
- **Folded.** `source/folded/texture_emissive.png` was noisy: about 18.3% of pixels were
  lit, including baked lighting on the white ceramic plates. The delivery
  `T_EnergyBlade_Folded_E.png` keeps only cyan / teal strip and pip pixels (and their hot
  white cores), with a 1-pixel feather. About 1.3% of pixels remain lit. The raw map is
  unchanged in `source/folded/`.

## Notes and issues

- The silhouettes are faithful to the Direction B concepts: a white ceramic grip with a
  dark wrap, a folding knuckle spine, two hinge disks at the top, and a slim single-edged
  emitter rail (locked out, or stowed against the grip with the cyan strip visible). It
  reads as a folding tool / short sabre, not a lightsaber, and there is no baked blade
  volume.
- **Flag — pommel-to-guard vs the 13–15 cm note.** At a 3.70 cm barrel (the hand-fit
  target, and the scale that puts deployed tip-to-pommel on 39.7 cm), pommel-to-guard is
  24.6 cm (Deployed) and 23.2 cm (Folded). The hinge crowns are large and the wrap is
  long relative to the brief. This is a mesh-proportion issue, not a scale typo. A 15 cm
  hilt would thin the barrel to about 2.3 cm.
- The two Rodin packs were generated separately and were not at the same raw barrel
  diameter, so each was scaled on its own barrel to 3.70 cm. The shared pivot is the
  wrap centre; the pommel differs by 0.6 cm on Z between the two meshes.
- No rig, no sockets, no UCX collision — please add those on import. This drop was not
  run through `blender-ai-mesh-cleanup`. These are two static meshes, not a single mesh
  with a pivoted blade part.
- Topology is Rodin's auto-triangulation (not clean quads). Tris are well under the 12k
  budget.

## Normal convention

`source/*/texture_normal.png` (and the normal embedded in both the raw and the derived GLB) is
**OpenGL** (Y+): it is the glTF normal, and the glTF 2.0 spec requires OpenGL tangent-space
normals. That matches how Rodin ships a glTF pack.

For Unreal, which expects **DirectX** (Y−), the delivery maps `T_EnergyBlade_*_N.png` have the
green channel inverted (`G' = 1 - G`). Red and blue are unchanged. This is the same convention
used for the accepted Drone, player-ship, Warden and Null fleet meshes. When importing the
loose maps, set N as a Normalmap (DirectX) and do **not** also use the GLB-embedded OpenGL normal.

## Import notes for the builders

- Target socket: the pilot's `hand_r`. Use the same socket transform for both meshes; the
  origin is the grip-wrap centre on each, with +Z along the grip and +X along the blade /
  stowed rail.
- Unreal: prefer the FBX at uniform scale 1.0. BC default / sRGB on; N as Normalmap,
  **DirectX**; ORM as Masks, sRGB off (R AO, G roughness, B metallic); E as emissive, sRGB
  on. The game tints the edge-strip mask.
- First check, Deployed: barrel Ø 3.70 cm, tip-to-pommel 39.7 cm, blade along +X, origin
  in the wrap, pommel at Z = −11.0 cm.
- First check, Folded: barrel Ø 3.70 cm, pommel-to-guard 23.2 cm, stowed rail along +X,
  same origin, pommel at Z = −10.4 cm.
