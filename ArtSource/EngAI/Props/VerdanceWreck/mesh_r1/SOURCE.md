## Derived delivery (what to import)

Cleaned, decimated, reoriented, pivoted and scaled in Blender 4.5.3. Source files were not
modified.

1. Removed **26 stray disconnected micro-fragments** with fewer than 15 triangles (124 faces),
   floating free of the hull. One 18-triangle debris chunk (~40 cm at delivery scale, against the
   mid-hull) was kept. The main hull stayed watertight.
2. Recalculated normals consistently, outward (volume proxy positive before and after scale).
3. `DECIMATE` `COLLAPSE` (UVs kept, `use_collapse_triangulate=True`, no boundary dissolve)
   at ratio **0.5413**, landing at **27,000 tris** / 13,060 unique verts (inside 26,000–28,000,
   strictly under 30,000). UVs stay in 0–1 (0 loops out of range). Topology stays watertight.
   Close-up checks of the ruptured ribs, broken wing, cockpit, rear turbines and the midsection
   through-hole showed no new holes or broken gaps.
4. Rotated **+90° about Z** so the cockpit / nose points **+X** (raw −Y → +X). Tail, turbines and
   fin point **−X**. The hero ruptured opening (hanging stairs, exposed ribs) faces **+Y**.
   +Z stays up.
5. Uniformly scaled so overall length (`max X − min X`) is **32.0 m**, then dropped so min Z = 0
   and the origin is the ground-base centre (mid X = 0, mid Y = 0).

Length was set to **3200.0 cm (32.0 m)** at the top of the R-030 26–32 m crashed-transport window
so the clear midsection through-hole is genuinely at least 200 cm wide and 250 cm high (see
walkability below). Nicholas's intact-silhouette board callouts 56.0 m long / 12.8 m tall; this
drop is the ruptured wreck at a walkable planet-side scale, not that intact figure.

### Walkability (R-030 / #39) — measured in Blender on the delivery mesh

The mid-fuselage is a true through-hole: a Y-axis ray in the opening misses the mesh entirely.
The largest axis-aligned clear rectangle inside that enclosed through-hole, measured on the
decimated, scaled delivery mesh:

| | |
|---|---|
| Clear gap width (along the fuselage, X) | **360.0 cm** |
| Clear gap height (Z) | **255.6 cm** |
| Opening X range | −56.0 to +304.0 cm (slightly forward of midships, toward the nose) |
| Deck / floor lip (min Z of the clear opening) | **276.9 cm** |
| Ceiling of the clear opening (max Z) | **532.6 cm** |
| 180 cm × 80 cm pilot box | stands on the deck inside the opening with ~75.6 cm of headroom; the 80 cm width sits easily in the 360.0 cm clear width |

The gap meets the R-030 requirement of at least **200 cm wide and 250 cm high**. Height was the
tight constraint: at 26–30 m overall length the through-hole would have been short of 250 cm, so
length was set to **32.0 m**. No interior snag triangles were trimmed; the opening is as Rodin
modelled it, after decimate only.

The existing deck / sill is **276.9 cm** above the ground. Hanging stairs drop from that deck
toward the ground, but they are not a walkable ramp and the deck itself is not a perfectly flat
slab. **Engineering should drop a flat floor slab at the existing deck height (~276.9 cm) inside
the ruptured midsection**, covering the clear opening (X −56.0 to +304.0 cm, through the beam).
A ramp or climb from ground up to that deck is also needed if the 180 cm pilot is to enter the
bay from terrain level; this file is the hero visual mesh, not a modular walkable kit.

**FBX (`SM_VerdanceWreck.fbx`).** Exported with the repo's Unreal convention
(`apply_unit_scale=True`, `apply_scale_options='FBX_SCALE_UNITS'`, `axis_forward='-Z'`,
`axis_up='Y'`, face smoothing, tangents, triangulated). The file's `UnitScaleFactor` /
`OriginalUnitScaleFactor` are **100** (centimetres). Reimported in Blender, the mesh
measures **32.0000 m** long at object scale 1.0, centred, min Z ≈ 0. Import with the
usual Interchange pipeline, uniform scale **1.0**; it should measure 3200.0 cm long in
Unreal.

**GLB (`SM_VerdanceWreck.glb`).** Vertex values are in **metres** (glTF's default unit),
with `export_yup=false`, so the file itself is +Z up / +X forward (POSITION accessor
X ±16.0, Y ±6.6625, Z 0–11.717) rather than the glTF-default Y-up convention. Prefer the
FBX with `UnitScaleFactor` 100 for Unreal. If an importer assumes glTF Y-up, it will
rotate the file; if it treats the numbers as metres with Z-up, use scale **1.0**; in
Unreal, if a glTF path treated the numbers as cm you would need scale **100**, which is
why the FBX is the one to import. The GLB embeds the OpenGL (glTF) normal, plus BC,
roughness and metallic. Do not also use the GLB-embedded OpenGL normal on top of
`T_VerdanceWreck_N.png`.

## Textures

All delivery maps are 2048 × 2048 PNG. **#39 uses BC / N / ORM only** — Rodin produced no
`texture_emissive.png`, and no fake emissive was invented.

| File | Role |
|---|---|
| `T_VerdanceWreck_BC.png` | Base Color, sRGB. Byte-identical copy of `source/texture_diffuse.png`. |
| `T_VerdanceWreck_N.png` | Normal, **DirectX**. Built from `source/texture_normal.png` by inverting the green channel (OpenGL → DirectX). |
| `T_VerdanceWreck_ORM.png` | Packed masks, sRGB off: **R = AO** (solid 255; no AO in the pack), **G = roughness**, **B = metallic**. Byte-identical to `source/texture_pbr.png`. |
| `contact_sheet.png` | Front +X (nose), Rear −X (turbines), Left +Y (opening), Right −Y, Top +Z (nose up), 3/4 Hero, a close-up of the ruptured midsection with a bright 180 cm × 80 cm pilot box standing on the deck in the gap, plus the BC / N / ORM swatches and the modelling-reference and Rodin-input thumbs. Rendered in Blender 4.5.3 EEVEE (headless). |

`source/texture_normal.png` (and the normal embedded in both the raw and the derived GLB) is
**OpenGL** (Y+): it is the glTF normal, and the glTF 2.0 spec requires OpenGL tangent-space
normals. That matches how Rodin ships a glTF pack.

For Unreal, which expects **DirectX** (Y−), the delivery map `T_VerdanceWreck_N.png` has the
green channel inverted. Set N as a Normalmap (DirectX) and do **not** also use the
GLB-embedded OpenGL normal.
