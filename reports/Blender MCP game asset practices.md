# Agents Build Clean Meshes; Hybrids Approach AAA

As of November 2026, Blender MCP agents are dependable technical artists but weak concept artists: on Blender 5.2.2 with the official Blender Lab MCP, Claude Code, Codex or Cursor can build, repair, measure, bake and export Unreal-ready meshes, yet code-only modeling plateaus at clean but toy-like results, so AAA-grade output in a four-day jam comes from a gated hybrid pipeline rather than from better prompts. The evidence is consistent: coding harnesses lift bpy script executability to about 0.97 without improving shape quality, vision-model judges agree with humans only 66% of the time, and this team's own code-built test fighter, with zero non-manifold edges and a full bevel and weighted-normal stack, was judged far below AAA. Quality therefore has to be divided by role: humans and concept references fix art direction and silhouettes; image-to-3D generators, CC0 libraries and a tested component library supply form; the agent owns structure, cleanup, naming, deterministic checks, multi-view review and export; and Unreal materials, Lumen and Nanite supply the finish. The official server is deliberately thin (26 tools, every mutation through `execute_blender_code`, no asset or generation tools), and on Windows it needs specific workarounds: add-on 1.0.3 with Online Access enabled, no `*_for_cli` tools, no `render_thumbnail_to_path`, and headless `blender.exe` from the shell for renders and batch jobs. The Unreal hand-off is a solved, calibratable recipe: one FBX per asset with FBX Units Scale, −Z/Y axes, Face smoothing, triangles and tangents, `UCX_`/`SOCKET_` naming, DirectX normals and ORM packing, imported through Interchange, which in UE 5.7 turns FBX materials into Material Instances whatever you ask for. Package it all as `.claude/skills` with a generated `.agents/skills` copy for Codex, because Claude Code still ignores `.agents/` and Codex reads only `.agents/skills` in a repository.

## The official Lab server is a 26-tool bridge with Windows traps

The Blender Lab MCP is a small, vendor-neutral bridge rather than a modeling toolkit. Its README promises a natural-language interface to Blender's Python API from a project that does no more than necessary ([Blender Lab README](https://projects.blender.org/lab/blender_mcp/src/branch/main/readme.md)): a Blender 5.1+ extension listens on `localhost:9876`, and a separate stdio `blender-mcp` process relays MCP calls to it ([add-on manifest](https://projects.blender.org/lab/blender_mcp/src/branch/main/addon/blender_mcp_addon/blender_manifest.toml)). Of its **26 tools, 20 are interactive and 6 are `*_for_cli` twins** that open a saved .blend in a background process. They cover file and scene summaries, search over bundled API and manual docs, screenshots, viewport navigation and two render tools, but **no tool models, assigns materials, searches asset libraries or generates meshes: every mutation goes through `execute_blender_code`**, which the server's own instructions call a last resort ([tool reference](https://projects.blender.org/lab/blender_mcp/src/branch/main/readme_tools.rst); [prompts.yml](https://projects.blender.org/lab/blender_mcp/src/branch/main/mcp/blmcp/data/prompts.yml)). The shape is intentional. Brecht Van Lommel asked the project to favor making Blender easier to learn and use over generative showpieces ([Blender forum](https://forum.blender.org/t/built-a-multi-agent-system-on-top-of-blenders-python-api-and-sharing-architecture-learnings-for-the-mcp-discussion/44260)), and Anthropic pitches the connector for scene analysis, debugging and batch scripting ([Anthropic](https://www.anthropic.com/news/claude-for-creative-work)). Generative work still runs well on it: the blender-kiln skill completed **20 of 20 asset briefs for $84.97** in API-equivalent cost, with wall times close to the community server's (a scripted lantern in 3.6 minutes, a PBR crate in 7.0, photo rebuilds in 17–19) ([blender-kiln](https://github.com/elithril/blender-kiln)). For a skills-based team the consequence is simple: all the leverage lives in the scripts, checks and rules you bring.

Agents fail on this server in predictable ways, and each failure has a rule. Every `execute_blender_code` call runs in a fresh namespace where **`bpy` is not pre-imported and no Python variables survive** ([#55](https://projects.blender.org/lab/blender_mcp/issues/55); [#53](https://projects.blender.org/lab/blender_mcp/issues/53)), so each call imports what it needs and re-finds objects by stable names in `bpy.data`. The return value must be **a dict assigned to `result`**, although the server prompt mentions lists ([#64](https://projects.blender.org/lab/blender_mcp/issues/64)), and Python exceptions come back as an ordinary tool result with an inner `error` status, so skills check that inner status instead of trusting the call's success flag ([cc-blender-skill backends](https://github.com/RobLe3/cc-blender-skill/blob/main/plugin/skills/text-to-blender/references/mcp-backends.md)). Code runs inside a timer callback on Blender's main thread ([execute_interactive.py](https://projects.blender.org/lab/blender_mcp/src/branch/main/addon/blender_mcp_addon/execute_interactive.py)), so viewport operators need an explicit `temp_override`, as the server's own screenshot and jump tools build, or a data-API replacement. The add-on's socket waits **300 s**, but Claude Desktop abandoned a long render at about **185 s** and marked the server unavailable ([#70](https://projects.blender.org/lab/blender_mcp/issues/70)); keep every call under roughly 150 s, and never resend a mutation that timed out until a fresh inspection shows whether it already ran ([cc-blender-skill backends](https://github.com/RobLe3/cc-blender-skill/blob/main/plugin/skills/text-to-blender/references/mcp-backends.md)). Inspection needs the same restraint: `get_objects_summary` on a 1,670-object scene returned about 904 KB and added roughly 15,600 input tokens ([#54](https://projects.blender.org/lab/blender_mcp/issues/54)), and `get_object_detail_summary` reports dimensions but no vertex or face counts, so evaluated triangle counts are computed in code. Every released bundle ships **Blender 5.1 docs**; 5.2 docs exist only on the unreleased main branch ([commit ff54e4d8](https://projects.blender.org/lab/blender_mcp/commit/ff54e4d8f6b09502f2f466189cca0e52b4a91643)), which is why the 5.2 API changes later in this report belong in every skill.

On the team's machine the server is only half installed. A local check found the Claude Desktop extension named Blender at v1.0.1 (which carries v1.0.0-era server code) and the lab.blender.org extension repository configured, but **no MCP add-on installed, Blender not on PATH and `BLENDER_PATH` unset** ([local validation](../research_notes/Blender%20MCP%20game%20asset%20practices/local_validation.md)). Bring-up therefore means installing add-on **1.0.3** from the Lab repository, where the drag-and-drop link must be dropped twice, once to add the repository and once to install ([MeltFlex](https://www.meltflexai.com/blog/connect-claude-to-blender)); ticking **Preferences › System › Allow Online Access**, without which the bridge never binds and only a small red label explains why ([#45](https://projects.blender.org/lab/blender_mcp/issues/45)); confirming in the add-on preferences that the server is running on 9876; and making a cheap read-only call such as `get_blendfile_summary_path_info` as the connection test. Version 1.0.3 matters because it carries the add-on half of the long-running screenshot-truncation fix ([commit 1e8d5976](https://projects.blender.org/lab/blender_mcp/commit/1e8d59762d97c199a9816396a665bae1a338f14f)); the older server inside the Claude Desktop extension still lacks the 2 KiB envelope headroom ([commit 4309a396](https://projects.blender.org/lab/blender_mcp/commit/4309a39646e644261624bfcd2bca669b343b7621)), so pass `size_limit_in_bytes` near 500,000 on screenshot calls. Anthropic's tutorial is stale on two points, citing Blender 4.2 and a sidebar tab, while the add-on requires 5.1 and keeps its controls in add-on preferences ([Claude Academy](https://academy.claude.com/tutorials/using-the-blender-connector-in-claude); [#22](https://projects.blender.org/lab/blender_mcp/issues/22)).

The Windows traps below were all reported on Windows 10 or 11 with Blender 5.2.x, and each has a workaround that belongs in the session skill.

A headless instance can also be driven through MCP when a teammate needs parallel batch work: `blender.exe --background --online-mode <file.blend> --command blender_mcp --port 9877`, with `--command` last, starts a synchronous bridge that a second server entry reaches through `BLENDER_MCP_PORT`, although screenshots and navigation are unavailable there ([cli.py](https://projects.blender.org/lab/blender_mcp/src/branch/main/addon/blender_mcp_addon/cli.py)).

Teammates on Codex or Cursor register the server by hand, because the Claude Desktop bundle defines no environment settings. The Lab wiki documents a clone at `C:\blender_mcp` launched with `uv` ([Setup wiki](https://projects.blender.org/lab/blender_mcp/wiki/Setup)); Claude Code does not expand `$HOME` in `.mcp.json`, so paths must be absolute ([#23](https://projects.blender.org/lab/blender_mcp/issues/23)); and the server reads `BLENDER_MCP_HOST` and `BLENDER_MCP_PORT` on every call ([connection.py](https://projects.blender.org/lab/blender_mcp/src/branch/main/mcp/blmcp/tools_helpers/connection.py)). Use **one server key, `Blender`, in every client**, so Claude Code's tool names stay `mcp__Blender__*` and skill permission rules keep matching ([Claude Code MCP](https://code.claude.com/docs/en/mcp)). OpenAI's migrator maps `.mcp.json` servers to `[mcp_servers.<name>]` tables in `.codex/config.toml` ([migrate-to-codex](https://github.com/openai/skills/blob/main/skills/.curated/migrate-to-codex/references/differences.md)); Cursor's `.cursor/mcp.json` takes the same `mcpServers` shape as Claude Code, which was not checked against Cursor's docs. {"mcpServers": {"Blender": {"command": "uv",
```json
  "args": ["--directory", "C:\\blender_mcp\\mcp", "run", "blender-mcp"],
  "env": {"BLENDER_MCP_PORT": "9876"}}}}
```

```toml

command = "uv"
```

The community server is the stronger generator front end and the weaker Windows citizen. ahujasid's project, with **34,144 GitHub stars**, was renamed `mcp-for-blender` in September 2026 to end confusion with the official server ([#366](https://github.com/ahujasid/mcp-for-blender/issues/366)). It now exposes nine tools, including `look`, which renders auto-framed multi-angle sheets in solid, material, wireframe or X-ray modes; `generate_3d` for Tripo, Hunyuan3D, Hyper3D Rodin and Meshy; and asset search across Poly Haven, Sketchfab and Poly Pizza. Its telemetry is on unless disabled ([README](https://github.com/ahujasid/mcp-for-blender); [YaroTech](https://note.com/yaoyoroztech/n/n2c1f2ff3cabe)). Its server instructions deserve copying into any skill: find shader nodes by type rather than by localized name, read enum identifiers instead of hard-coding them, put material colors on shader inputs rather than the viewport color, request one object per generation, and size every imported or generated model from its world bounding box before setting it on the ground ([server.py](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/server.py)). Its tracker also records socket timeouts, a 4-minute client cancellation ([#279](https://github.com/ahujasid/mcp-for-blender/issues/279)) and a Blender 5.2 LTS Windows report in which commands are accepted but never executed ([#299](https://github.com/ahujasid/mcp-for-blender/issues/299)). The practical split follows YaroTech's comparison, official for inspection and automation and community for generation: keep the official server as the jam's main bridge, and either run the community server beside it on its own port, moving the official one to 9877 through `BLENDER_MCP_PORT` ([cc-blender-skill backends](https://github.com/RobLe3/cc-blender-skill/blob/main/plugin/skills/text-to-blender/references/mcp-backends.md)), or call generators outside Blender and import their files with a cleanup script. Because only one client should drive a Blender session at a time ([mcp.directory](https://mcp.directory/blog/claude-blender-connector-guide)), each teammate runs a separate Blender. Both servers execute arbitrary Python with the user's rights: the Lab recommends a VM or a machine without sensitive data ([readme v0.3.0](https://projects.blender.org/lab/blender_mcp/src/tag/v0.3.0/readme.rst)), its weak sandbox blocks little beyond quitting and factory resets ([weak_sandbox.py](https://projects.blender.org/lab/blender_mcp/src/branch/main/addon/blender_mcp_addon/weak_sandbox.py)), and Online Access does not restrict Python, so skills never pre-approve `execute_blender_code` or add network calls to it.

## Code-only modeling plateaus at clean but toy-like

### Harnesses fix the code, not the shape

The benchmark literature has converged on an uncomfortable result for anyone hoping prompts alone will yield hero art. On 3DCodeBench (212 tasks, Blender 5.0), two error-feedback retries raise script executability from **0.692 to 0.972**, roughly **90% of baseline failures are Blender API mismatches** such as the removed `Mesh.use_auto_smooth`, and running models inside Claude Code, Codex CLI or Gemini CLI pushes executability to 0.97–0.995 while shape similarity slips by 0.010: **harnesses fix API errors, not shapes** ([3DCodeBench](https://arxiv.org/html/2606.01057v1)). The same benchmark rated Claude Opus 4.7 the most reliable coder (0.910 executability) but the least preferred by human voters (Elo 1006 against GPT-5.5's 1163), with simplistic, floating primitives; Opus 5.5 was not tested. Vision feedback is weaker than it looks. On BlenderGym the best vision-language systems trail average Blender users by about 5× on geometry edits and 26× on object placement, and their pairwise judgments match human preference **66%** of the time, against 79% between humans ([BlenderGym](https://arxiv.org/html/2504.01786v1)). Visual self-critique, tested on Gemini and Gemma models, moved text-to-3D similarity by at most +0.0085 and made image-conditioned results worse for four of five models ([3DCodeBench](https://arxiv.org/html/2606.01057v1)), and SimWorlds caught a visual-only verifier accepting scenes that had been faked to look right ([SimWorlds](https://arxiv.org/html/2607.01766v1)).

Practitioners hit the same ceiling. MindStudio's field test lists organic shapes, characters, faces, foliage, clean topology, complex modifier stacks, multi-object alignment, procedural textures, Geometry Nodes and proportion judgment as weak spots ([MindStudio](https://www.mindstudio.ai/blog/claude-blender-mcp-real-world-performance)); an Opus 5.5 creature project produced a 1.4M-polygon set and a 115-bone rig, but also a toy-like hero and a finger through a branch that needed a manual fix ([JQ Visions](https://visions.joaoqueiros.com/blog/claude-opus-5-5-blender-mcp-3d-modeling-rigging-animation-workflow/)); MeltFlex's interior brief hit exact dimensions yet delivered rounded blocks, no glass and a flat sky ([MeltFlex](https://www.meltflexai.com/blog/connect-claude-to-blender)). The team's own test is the most relevant data point. A 10-part fighter built in code, with a lofted hull, swept wings, lathed nacelles, a bevel, harden-normals and weighted-normal stack, four materials and zero non-manifold edges, was judged by the user to be far below AAA: clean, but simplistic and toy-like ([local validation](../research_notes/Blender%20MCP%20game%20asset%20practices/local_validation.md)). **Technical cleanliness and art quality are separate axes, and agents maximize only the first.**

What code does reliably is everything around the art. The same field reports rate hard-surface and geometric scenes, basic Principled materials, duplication and arrangement, and utility scripts as strengths ([MindStudio](https://www.mindstudio.ai/blog/claude-blender-mcp-real-world-performance)), and the team's headless runs on Blender 5.2.2 produced watertight procedural asteroids and crystals, repaired and rebaked a simulated AI mesh, and round-tripped an FBX with exact collision and socket names ([local validation](../research_notes/Blender%20MCP%20game%20asset%20practices/local_validation.md)). Doc grounding widens the vocabulary, since LL3M's Blender-doc retrieval raised complex operations per script from 1.20 to 5.86 and cut execution errors by 26% ([LL3M](https://arxiv.org/html/2508.08228v1)), but richer operations without a design still produce well-built toys. The agent's role is technical artist and pipeline engineer: assembly, cleanup, naming, measurement, baking and export, plus fast iteration on a design someone else has fixed.

### AAA comes from direction, sourced form and engine finishing

The levers that move perceived quality sit before and after the modeling code. Before it, art direction has to be explicit. kiln requires a palette of 3–5 colors, each with a role and only one accent, at least three materials on any multi-part object, and at least three finishes: bevels on every visible edge, wear where hands go and a detail at each end ([kiln review rounds](https://github.com/elithril/blender-kiln/blob/HEAD/plugin/references/review-rounds.md)). The blender-agent-studio intake skill forbids silently choosing realistic versus cartoon treatment and asks one to three high-impact questions first ([art-direction intake](https://github.com/ifBars/blender-agent-studio/blob/HEAD/plugins/blender-agent-studio/skills/blender-art-direction-intake/SKILL.md)). References help in a specific way. A generated target image lifted BlenderAlchemy's material-editing CLIP score from 25.2 to 28.2 ([BlenderAlchemy](https://arxiv.org/html/2404.17672v1)), and reference images were critical to CADCodeVerify's yes/no verification ([CADCodeVerify](https://arxiv.org/abs/2410.05340v1)), yet giving 3DCodeBench's coders one to four reference views changed results by at most 0.012 ([3DCodeBench](https://arxiv.org/html/2606.01057v1)). Concept sheets are for deciding silhouettes and writing verification questions, not a magic input to the code.

During modeling, enforce a detail hierarchy. Proportions lock before panel detail, the blockout survives until the silhouette is approved, and silhouettes are checked at 45° increments ([arjun988 hard-surface](https://github.com/arjun988/blender-skills/blob/HEAD/.claude/skills/hard-surface/SKILL.md)). More parts are not evidence of quality; when small detail adds little, revisit primary and secondary form instead ([blender-review-optimize](https://github.com/SamuelAsherRivello/ai-skills-blender/blob/HEAD/skills/blender-review-optimize/SKILL.md)). The tells of cheap CG are well known: razor-sharp edges ([MartinRapcan skill](https://github.com/MartinRapcan/blender-claude-skill/blob/HEAD/blender/SKILL.md)), hard shadows on sharp geometry and plastic-looking uniform roughness ([blender-pro-workflow](https://github.com/RobLe3/cc-blender-skill/blob/HEAD/plugin/skills/blender-pro-workflow/SKILL.md)), and pure-black or pure-white base colors, so keep albedo between about 0.02 and 0.9 and mix a little noise into roughness ([ahujasid materials guide](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/materials.md)).

After modeling, review in rounds with fresh eyes. kiln found its building session reported nothing wrong over a chair with black holes and a mascot whose hair read as horns, so each round now goes to a new subagent that sees only the brief, the reference and the render sheets, never the build log or scripts; hero briefs get at least 6 and at most 12 rounds, props 1–8, and review stops after two clean fresh readings. The evidence is anecdotal but pointed: a chibi shipped after two looks was rated low quality by its user, while a mascot built over six rounds was rated decent ([kiln review rounds](https://github.com/elithril/blender-kiln/blob/HEAD/plugin/references/review-rounds.md)). A human remains the final gate for hero art, topology, UVs, rigging, consistency, performance and licensing ([best-games.io](https://best-games.io/blog/codex-claude-code-blender-mcp-game-development-guide)).

Much of the AAA look is engine-side. Blender's procedural shader nodes and toon ramps do not survive FBX or glTF export, and emission arrives as an emissive value on a black base rather than as a glow ([EL4CTEO stylized](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-stylized-npr/SKILL.md); [kiln SKILL.md](https://github.com/elithril/blender-kiln/blob/HEAD/SKILL.md)), so glow, bloom and stylization belong in Unreal master materials, where emissive values above 1.0 drive bloom ([Epic emissive](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-the-emissive-material-input-in-unreal-engine)). Nanite changes the geometry budget for static opaque meshes: dense geometry ships with no LODs and no normal-map bake ([EL4CTEO Unreal reference](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-export-pipelines/references/unreal.md); [Epic Nanite](https://dev.epicgames.com/documentation/en-us/unreal-engine/nanite-virtualized-geometry-in-unreal-engine)), which makes decimated generator output and kitbashed density viable for rocks, hulls and megastructures without retopology. In a four-day jam, AAA-adjacent means fixed art direction, sourced form, agent-perfected technicals and Unreal look development, not more modeling code.

### Route each asset class to where quality lives

ahujasid's scene guide draws the boundary most sources share: script simple or procedural geometry such as walls, floors, stairs, arrays and scatters, and generate hero objects or anything specific, never a whole scene, the ground or parts meant for assembly ([scene guide](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/scene.md)); MindStudio adds libraries to avoid modeling from scratch and manual modeling where production quality matters ([MindStudio](https://www.mindstudio.ai/blog/claude-blender-mcp-real-world-performance)). Applied to the team's space shooter, Triad Drift, with code always owning cleanup, naming, checks and export, the routing looks like this:

| Asset class | Route | LOD0 planning budget (tris) | Unreal path |
|---|---|---|---|
| Hero ships | Concept sheet (front, side, top) → generated base (Rodin Quad + PBR, 30–60k) or kitbash from the component library → agent adds bevel tiers, sockets, emissive masks and collision → human silhouette gate | Hull 30k–150k; glass and FX meshes 0.5k–3k | Nanite hull; separate non-Nanite canopy and FX meshes |
| Enemy ships | Parametric variants of hero components with palette swaps | 8k–40k | Nanite, instanced |
| Mothership, megastructures | Code kitbash from collection instances and arrays, split into 4–16 sections | 200k–2M total | Nanite sections |
| Asteroids, rocks | Code procedural (displaced icosphere → voxel remesh) or Poly Haven CC0 | 20k–200k per variant | Nanite plus instancing |
| Crystals | Code (hex prism with a poked tip) and an emissive material | 1k–20k | Nanite when opaque; translucent variants non-Nanite |
| Alien flora, organic props | Image-to-3D plus cleanup, or shallow curve and Geometry Nodes code; masked cards for thin leaves | 2k–20k | Masked Nanite, or classic mesh with LODs |
| Modular corridor kit | Code on a fixed grid, origin at the snapping corner, walls at least 10 cm thick | 0.5k–20k | Nanite optional |
| Small props | Code, or a CC0 library model restyled to the palette | 1k–15k | Either |
| Energy blade, shields | Simple code mesh; the look comes from a translucent or additive Unreal material plus Niagara | 200–2k | Non-Nanite |
| Humanoid crew | Never code-modeled: image-to-3D in A- or T-pose or a library character, rigged or retargeted in Unreal; or redesigned as hard-surface robots | 15k–40k | Skeletal mesh via FBX |

The triangle figures are planning numbers, not a published standard, because published ranges disagree: ahujasid's retopology guide gives 15–50k triangles for a hero game character and 500–5k for a prop ([retopology guide](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/retopology.md)), while EL4CTEO gives 50–150k and 5–50k for console and PC and calls millions acceptable for static Nanite meshes ([game optimization](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-game-optimization/SKILL.md)). The 10 cm wall minimum and the preference for separate wall and floor meshes are Epic's Lumen guidance ([Lumen technical details](https://dev.epicgames.com/documentation/en-us/unreal-engine/lumen-technical-details-in-unreal-engine)).

Fix generator defects at generation time, because cleanup costs more than prevention. Generated meshes arrive dense, unitless or normalized, arbitrarily oriented, littered with floaters and sometimes with lighting baked into the albedo; Hunyuan3D 2.1's own post-processing, for example, rescales every mesh to a 1.2-unit bounding sphere and reduces it to 40,000 faces by default ([Hunyuan3D postprocessors](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/main/hy3dshape/hy3dshape/postprocessors.py)). The settings and licence terms that matter for a jam that ships its build:

| Generator | Settings that prevent cleanup | Licence for shipped output |
|---|---|---|
| Hyper3D Rodin Gen-2 | `meshMode` Quad for hero bases or Raw for dense statics; `material` PBR, since Shaded bakes lighting into the texture; custom `polyCount` (Quad 1k–200k); `taPose` for humanoids ([Runware Rodin guide](https://runware.ai/docs/models/hyper3d-rodin-gen-2/guides/topology-and-polygon-budget)) | Commercial use depends on the plan, and outputs may not be used to train AI models ([Hyper3D terms](https://hyper3d.ai/legal/terms)) |
| Tripo v3.1 | `face_limit` or `smart_low_poly` (500–20k tris); `pbr` on; `delight`, which only the v3.5 texture model reads; `auto_size`, off by default; verify `export_orientation`, which defaults to +x and reports success even when wrong ([Tripo API](https://developers.tripo3d.com/en/docs/generation-image-to-model/standard)) | The free-tier terms contradict each other, so use a paid plan or don't ship free output ([Tripo help](https://www.tripo3d.ai/help/privacy-policy/how-to-use-tripo-models-commercially); [Tripo blog](https://www.tripo3d.ai/blog/commercial-use-ai-3d-models)) |
| Meshy 7.1 | `topology` quad; `target_polycount` (default 30k); `enable_pbr`, off by default; `remove_lighting`, Meshy 6 textures only; `auto_size` with `origin_at` bottom; `save_pre_remeshed_model` keeps a dense bake source ([Meshy API](https://docs.meshy.ai/en/api/image-to-3d)) | Free tier is CC BY 4.0 with attribution; Pro and above are private ([Meshy pricing](https://docs.meshy.ai/en/webapp/pricing)) |
| Hunyuan3D 2.1, self-hosted | About 10 GB VRAM for shape and 29 GB with texture ([Hunyuan3D 2.1](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1)) | The licence does not apply in the EU, UK or South Korea, and output may not be used outside its territory ([LICENSE](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/main/LICENSE)) |

Prompting rules from kiln keep generations usable: one object per call, never the ground or environment, a single view by default, and concept images on a transparent or plain white background ([kiln SKILL.md](https://github.com/elithril/blender-kiln/blob/HEAD/SKILL.md); [kiln AI generation](https://github.com/elithril/blender-kiln/blob/HEAD/plugin/references/ai-generation.md)). One 2025 Blender comparison found Hunyuan3D's raw geometry cleanest, with Meshy and Tripo needing moderate cleanup ([Top3D](https://www.top3d.ai/learn/retopology-comparison-2025)). Library sources carry their own traps: Poly Haven is CC0 and its models import best from .blend with 1K–2K textures, but downloads block Blender's main thread, and about 69% of Poly Pizza is CC-BY, so filter to CC0 or record attribution ([ahujasid README](https://github.com/ahujasid/mcp-for-blender)); mixing low-poly library props with photoreal scans in one frame breaks the style ([scene guide](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/scene.md)). Every generated or library asset needs a provenance record of source, model version, plan tier, date, input, licence and post-processing.

## A gated loop puts numbers before pictures

The research agrees on loop structure even where it disagrees on details. Staged construction beats one shot: removing staged construction dropped SimWorlds' visual score from 0.87 to 0.76, and removing its deterministic verifier cut the structural pass rate from 0.97 to 0.87 ([SimWorlds](https://arxiv.org/html/2607.01766v1)). Editing a persistent script beats regenerating: LL3M's coder produced a substantially different asset whenever it lost the shared code context ([LL3M](https://arxiv.org/html/2508.08228v1)), and BlenderGym's coders mismatched their edits in scripts longer than about 80 lines ([BlenderGym](https://arxiv.org/html/2504.01786v1)). A reusable component library compounds: SceneCraft's learned library lifted CLIP similarity from 48.3 to 69.8 ([SceneCraft](https://arxiv.org/html/2403.01248v1)), and retrieving three similar working examples raised compile success from 40.8% to 70.0% ([BlenderRAG](https://arxiv.org/html/2605.00632)). And the best version must always survive: BlenderAlchemy's quality peaked at the third edit and degraded once revert-to-best was removed ([BlenderAlchemy](https://arxiv.org/html/2404.17672v1)). In skill form this means one generator script per asset as the source of truth, edited function by function in units under about 80 lines; a docs lookup through `search_api_docs`, `get_python_api_docs` or live introspection before any API not yet used successfully in the session; two retries with a truncated traceback, then a docs lookup and a rewrite of the smallest failing function ([3DCodeBench](https://arxiv.org/html/2606.01057v1)); and, after two failures of the same approach, a change of approach class, with a human consulted after three ([jangtrinh operating rules](https://github.com/jangtrinh/design-os-3d-blender/blob/HEAD/.agents/rules/blender-agent-operating-rules.md)).

Every asset then climbs the same ladder, and no stage starts until the previous gate passes.

| Stage | Agent actions (official MCP) | Exit gate |
|---|---|---|
| 0. Preflight | `get_blendfile_summary_path_info`, then progressive `get_objects_summary`; confirm Metric units at scale 1.0, a visible Blender window and the asset's own .blend | Connection answered; live or headless path stated |
| 1. Brief | Target dimensions, forward axis, origin rule, name prefix and collection, triangle and material-slot budgets, palette roles, reference or concept, route, explicit exclusions | Human approves after at most three questions |
| 2. Blockout | Primitives and Mirror only, at real scale beside a scale reference such as a 1.8 m capsule; report dimensions and triangles per object; checkpoint `_v01_blockout` | Dimensions in tolerance; four-view and game-camera silhouette approved by a human |
| 3. Primary forms | One function per part, or import and clean a generated base; parts overlap at their joints | Mesh report and assembly check pass; one framed screenshot per part |
| 4. Secondary detail | Bevel tiers, weighted normals, insets and panel lines, instanced greebles, booleans | No non-manifold edges on closed parts; budget held; contact-sheet round |
| 5. Materials, UVs, bake | Few slots, Principled values, Smart UV and pack, BC/N/ORM/E bake from the triangulated low-poly | Maps exist with correct color spaces; second-angle look after texturing |
| 6. Game-ready prep | Apply transforms, set origin, add `UCX_` and `SOCKET_` children, triangulate, decide Nanite or LODs | Unreal validator reports zero errors |
| 7. Export and round-trip | One FBX per asset plus manifest; re-import into a fresh scene; Unreal import and post-fix | Names, scale 1.0, dimensions, collision, sockets and materials match; size checked against a 180 cm mannequin |
| 8. Review rounds | Fresh reviewer reads the sheet and the yes/no list; one targeted fix per issue; revert if worse | Two clean fresh readings or the round cap; human ship or no-ship |

The four-view blockout gate and the early export of one representative module come from best-games.io's game-asset pipeline ([best-games.io](https://best-games.io/blog/codex-claude-code-blender-mcp-game-development-guide)); the export copy and isolated re-import from blender-game-export ([blender-game-export](https://github.com/SamuelAsherRivello/ai-skills-blender/blob/HEAD/skills/blender-game-export/SKILL.md)); and the rule that numbers, QA, a look and non-zero export files all precede calling an asset done from EL4CTEO ([blender-core](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-core/SKILL.md)). Checkpoints are numbered .blend files per stage, and every part comes from a re-runnable script that never stacks edits ([staged-3d-build](https://github.com/Benners24/staged-3d-build/blob/HEAD/skill/staged-3d-build/SKILL.md)); kiln adds one asset at a time and no silent destruction, so decimation, simplification and deletion are always proposed before they happen ([kiln SKILL.md](https://github.com/elithril/blender-kiln/blob/HEAD/SKILL.md)).

Hard gates are deterministic and run at every stage. Names and hierarchy come first: asset prefix, correct collection, no `.001` suffixes, every registered part present. Dimensions must sit within a proposed ±5% of the brief, measured on world-space vertices rather than `bound_box`, which overstates rotated objects (a windmill read 104.8 mm instead of 90.0) ([kiln SKILL.md](https://github.com/elithril/blender-kiln/blob/HEAD/SKILL.md)); `Object.dimensions` includes modifiers but ignores rotation ([dcc-mcp pitfalls](https://github.com/dcc-mcp/dcc-mcp-blender/blob/HEAD/skills/dcc-blender-assembly-pitfalls/SKILL.md)), and grounded props are checked at their lowest visible contact, because nominal centers leave rounded feet floating ([blender-create-model](https://github.com/SamuelAsherRivello/ai-skills-blender/blob/HEAD/skills/blender-create-model/SKILL.md)). Attachment uses a BVH nearest-distance check with joints overlapping by at least 5 mm, since touching is not joined and a 5 mm gap is visible ([Assembly skill](https://github.com/ProfRino/Blender-MCP-Assembly-Skill/blob/HEAD/SKILL.md)); the team's assembly check flagged a floating nose ring with a 0.39 m gap in about a second. Mesh health means no non-manifold edges on closed parts, no loose vertices, consistent winding and no unapplied or negative scale; the team's report script catches flipped faces with `BMEdge.is_contiguous` and inside-out shells by negative signed volume ([local validation](../research_notes/Blender%20MCP%20game%20asset%20practices/local_validation.md)). EL4CTEO's QA table supplies the fixes: surfaces within 1 mm z-fight and need deleting or offsetting by 2–5 mm, floating parts snap or join, n-gons are acceptable only on flat faces that never deform, and data maps tagged sRGB become Non-Color ([blender-asset-qa](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-asset-qa/SKILL.md)). Budgets close the list: evaluated triangles per object and in total, and material slots per asset, with proposed ceilings of three for props and five for heroes.

Pictures come after the numbers, as one contact sheet rendered from the stage checkpoint.

| Tile | Settings on Blender 5.2.2 | What it judges |
|---|---|---|
| Clay three-quarter, plus orthographic front, side and top | Workbench `STUDIO`, cavity `BOTH`, object outline, `color_type='MATERIAL'` (which reads `diffuse_color`), one shared orthographic scale | Proportion, primary and secondary form, bevel highlights |
| Silhouettes from top, side and game camera | Workbench `FLAT`, `SINGLE` color black, world color white | Readability, and whether the hero ships differ from each other |
| Matcap three-quarter | `light='MATCAP'` set before `studio_light='check_normal+y.exr'` | Bent normals and smoothing seams |
| Wireframe three-quarter | Duplicate with a `WIREFRAME` modifier (`use_replace`) and `OBJECT` colors | Evaluated topology and density |
| Material three-quarter and rear | EEVEE at 16 samples, bundled HDRI lighting behind a flat grey camera backdrop, an area key light, compositor Glare bloom, `Standard` view transform | Color, materials and glow |

The sheet renders headless in seconds: 512 px tiles took 0.04–0.9 s each and an 11-tile sheet about 4 s on the team's RTX 5080 ([headless 5.2.2 tests](../research_notes/Blender%20MCP%20game%20asset%20practices/bpy_techniques_blender5.md)), and the team's `review_renders.py` builds it in a temporary scene that leaves the user's scene untouched ([local validation](../research_notes/Blender%20MCP%20game%20asset%20practices/local_validation.md)). Render it from the saved checkpoint with headless Blender rather than inside the GUI, which sidesteps the render-tool bugs and keeps the main thread free, and never let a headless process write into the file the GUI has open ([jangtrinh operating rules](https://github.com/jangtrinh/design-os-3d-blender/blob/HEAD/.agents/rules/blender-agent-operating-rules.md)). The research rigs agree on coverage: four azimuths at 45°, 135°, 225° and 315° ([3DCodeBench](https://arxiv.org/html/2606.01057v1)), five views fitted to the bounding box ([LL3M](https://arxiv.org/html/2508.08228v1)), or cameras at the bounding-box corners ([VIGA](https://arxiv.org/html/2601.11109v2)).

Visual judgment then runs as a checklist rather than an opinion. Before looking, the agent writes 5–10 yes/no questions from the brief, together with the expected answer and what would falsify it ([jangtrinh operating rules](https://github.com/jangtrinh/design-os-3d-blender/blob/HEAD/.agents/rules/blender-agent-operating-rules.md)); it answers each from the sheet and feeds back only the failures, the loop with which CADCodeVerify cut point-cloud error by 7.3% ([CADCodeVerify](https://arxiv.org/abs/2410.05340v1)); and after each fix pass it re-checks that every critique was actually applied, because LL3M's coder routinely applied only some of them ([LL3M](https://arxiv.org/html/2508.08228v1)). The reviewer keeps a ledger marking each critical requirement pass, fail or unclear, citing the view that proves it, and names, code or metrics can never turn an absent or occluded feature into a visual pass ([iterative refinement](https://github.com/ifBars/blender-agent-studio/blob/HEAD/plugins/blender-agent-studio/skills/blender-iterative-refinement/SKILL.md)). When two candidates are compared, the comparison runs twice with the order swapped, since BlenderGym found position bias in some judges ([BlenderGym](https://arxiv.org/html/2504.01786v1)).

Inside the live session, cheap screenshots track progress between gates. kiln measured agents on the official server taking a single screenshot in four of five sessions and framing the subject once in five, so it now requires `jump_to_view3d_object_by_name` followed by `get_screenshot_of_area_as_image(area_ui_type="VIEW_3D")` after every phase that changed geometry or materials, plus a second angle after texturing, which means at least four captures per asset ([kiln Lab MCP reference](https://github.com/elithril/blender-kiln/blob/HEAD/plugin/references/blender-mcp.md)). The jump tool forces Object mode and changes the selection, so selection must be re-set afterwards ([jump toolcode](https://projects.blender.org/lab/blender_mcp/src/branch/main/mcp/blmcp/tools/jump_to_view3d_object_by_name_toolcode.py)); materials and lighting are judged on renders, not viewport captures ([cc-blender-skill backends](https://github.com/RobLe3/cc-blender-skill/blob/main/plugin/skills/text-to-blender/references/mcp-backends.md)); and three or four screenshots per turn are fine, while about thirty per session noticeably raises cost ([mcp.directory](https://mcp.directory/blog/claude-blender-connector-guide)). Token hygiene matters more than tool count. Across 72 measured Claude Code sessions on Blender 5.2.2, everyday tasks consumed 69,000–126,000 input tokens ($0.16–$0.23), a property dump of 580 objects cost $0.87, and truncating long results to the first 2,000 and last 1,000 characters cut that task's cost by 81% ([#347](https://github.com/ahujasid/mcp-for-blender/issues/347)); the measurer maintains the measuring tool, so treat the figures as indicative. Return small dicts, redirect noisy stdout, batch checks into one call and skip GLB exports while iterating ([space-station-generator AGENTS.md](https://github.com/Psijic/space-station-generator/blob/HEAD/AGENTS.md)).

A stage advances when every hard gate passes and every yes/no answer is yes, or after three visual rounds, keeping the best snapshot and logging what remains for a human; that stop rule is a proposed default rather than a measured optimum. Measured runs give the time scale: LL3M averaged about 10 minutes per object ([LL3M](https://arxiv.org/html/2508.08228v1)), and kiln's runs on the official server took 3.6–8.6 minutes for props and small batches and 17–19 minutes for photo rebuilds ([blender-kiln](https://github.com/elithril/blender-kiln)). For a four-day jam this argues for spending day one on the calibration round-trip, the component library and the review harness before any hero asset, then pushing assets through the ladder in parallel Blender instances. Benners24's short-deadline path, which merges detail passes, does UVs and wear in one step and stops at one hero render, shows which stages can be compressed without skipping a gate ([staged-3d-build](https://github.com/Benners24/staged-3d-build/blob/HEAD/skill/staged-3d-build/SKILL.md)).

## Blender 5.2 recipes that survive the API drift

The hard-surface stack below was verified headless on the team's Blender 5.2.2, where it produced custom corner normals that survive `object.convert` and an FBX export with tangents ([headless 5.2.2 tests](../research_notes/Blender%20MCP%20game%20asset%20practices/bpy_techniques_blender5.md)); parameter ranges come from EL4CTEO and arjun988 ([EL4CTEO hard-surface](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-hardsurface-modeling/SKILL.md); [arjun988 hard-surface](https://github.com/arjun988/blender-skills/blob/HEAD/.claude/skills/hard-surface/SKILL.md)), and the API definitions from Blender's reference ([BevelModifier](https://docs.blender.org/api/5.1/bpy.types.BevelModifier.html); [WeightedNormalModifier](https://docs.blender.org/api/5.1/bpy.types.WeightedNormalModifier.html); [TriangulateModifier](https://docs.blender.org/api/5.1/bpy.types.TriangulateModifier.html)).

| Step | Settings | Why |
|---|---|---|
| Base shading | `mesh.shade_smooth()`; never `use_auto_smooth`, removed in 4.1 | Custom normals from the stack drive the shading |
| Mirror | `use_axis=(True, False, False)`; bisect and clip for wings | Centerline symmetry is set early |
| Boolean | `solver='EXACT'` (`FAST` is now `FLOAT`; `MANIFOLD` needs closed inputs); `material_mode='TRANSFER'`; `CUT_` cutters in their own collection, `display_type='WIRE'`, `hide_render`, extended past the surface | `INDEX` mode left an empty material slot on the result |
| Bevel | `limit_method='ANGLE'` at 30–35°, `use_clamp_overlap`, `harden_normals`, `miter_outer='MITER_ARC'`, 2–3 segments; width about 0.5–2% of the part, in tiers of 5–20 mm for primary edges, 1–3 mm for panel lines and 0.5–1 mm for micro detail | Razor-sharp edges read as cheap CG |
| Weighted Normal | `mode='FACE_AREA'`, `weight=50`, `keep_sharp=True` | Large flat faces stay flat; avoid UV seams across face-weighted bevels, which double vertices ([Polycount](https://polycount.com/discussion/comment/2577165)) |
| Triangulate | Last in the stack; `min_vertices=5` for n-gons only, or all faces; `keep_custom_normals=True` | FBX cannot export tangents for meshes with n-gons and only prints a warning |
| Apply | `bpy.ops.object.convert(target='MESH')`, join under `temp_override`, then `material_slot_remove_unused()` | One call applies every modifier and keeps the custom normals |

Round parts use segment counts in multiples of four or eight: 6–8 for bolts, 12–16 for handles, 24–32 for barrels and 48 or more for close-up hero parts ([EL4CTEO hard-surface](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-hardsurface-modeling/SKILL.md)). Panel lines come cheaply from `bmesh.ops.inset_individual`, whose original faces become the inner panels and can take their own material index, and raised greebles from `extrude_discrete_faces` plus a translate along the normal; repeated detail is instanced, never modeled uniquely ([headless 5.2.2 tests](../research_notes/Blender%20MCP%20game%20asset%20practices/bpy_techniques_blender5.md); [bmesh.ops](https://docs.blender.org/api/5.1/bmesh.ops.html)). Primitives hide factor-of-two traps: `primitive_cube_add(size=1)` spans ±0.5, bmesh `create_*` operators default to size zero, primitives spawn at the 3D cursor, rotated cylinders make poor beams (build the A-to-B geometry in bmesh instead), and anything meant to subdivide should extend 10–15% past its target ([Assembly skill](https://github.com/ProfRino/Blender-MCP-Assembly-Skill/blob/HEAD/SKILL.md); [dcc-mcp pitfalls](https://github.com/dcc-mcp/dcc-mcp-blender/blob/HEAD/skills/dcc-blender-assembly-pitfalls/SKILL.md)). Weld only after applying transforms: merging before applying a scale of 100 deleted 108 of 928 faces, and a plain merge re-smoothed a faceted mesh so that bent corners rose from 26.7% to 94.5% ([kiln SKILL.md](https://github.com/elithril/blender-kiln/blob/HEAD/SKILL.md)).

The team's own render-and-critique loop on 5.2.2 surfaced a failure catalog that belongs in the Gotchas section of every modeling skill ([local validation](../research_notes/Blender%20MCP%20game%20asset%20practices/local_validation.md)).

| Symptom | Fix |
|---|---|
| An angle-limited bevel at a sharp cone-to-body junction collapses into coincident vertices | Add an intermediate (ogive) section and weld at export |
| Inset on tiny faces collapses into duplicates | Inset only faces larger than about 16 × thickness² |
| A boolean result gains an empty material slot | Give cutters the target's material or use `TRANSFER`, and remove unused slots after joining |
| Edit-mode operators fail their poll under `temp_override(active_object=...)` | Set `view_layer.objects.active` and the selection for real, then restore them |
| Exported copies are silently renamed `.001`, so Unreal cannot pair `UCX_` collision with the mesh | Temporarily rename the originals during export |
| Metallic hulls bake black in a Cycles DIFFUSE color bake, which multiplies by one minus metallic | Bake Principled inputs through a temporary Emission shader (EMIT pass) |
| Unrelated scene objects darken AO bakes | Hide everything except the target and its sources |
| Collapse-decimating a noisy surface leaves shard-like slivers | Choose density at generation time instead |
| Sharp-by-angle shading makes organic rocks look faceted | Use plain smooth shading for rocks |
| Emission strength of 3 or more under AgX washes saturated glow to white | Review with emission between 0.5 and 3 and the Standard view transform |
| Broad color noise alone bakes an almost flat normal map | Drive bump from a separate high-frequency noise |

Most generated-code failures on 5.2.2 trace to a short list of renames, each confirmed on the installed build ([headless 5.2.2 tests](../research_notes/Blender%20MCP%20game%20asset%20practices/bpy_techniques_blender5.md)) against the [4.0](https://developer.blender.org/docs/release_notes/4.0/python_api/), [4.1](https://developer.blender.org/docs/release_notes/4.1/python_api/), [5.0](https://developer.blender.org/docs/release_notes/5.0/python_api/) and [5.2](https://developer.blender.org/docs/release_notes/5.2/python_api/) Python API notes.

| Habit from older tutorials | Blender 5.2.2 replacement | Changed in |
|---|---|---|
| `render.engine = 'BLENDER_EEVEE_NEXT'` | `'BLENDER_EEVEE'`; the old id raises a TypeError | 5.0 |
| `mesh.use_auto_smooth`, `auto_smooth_angle`, `calc_normals_split()` | `bpy.ops.object.shade_auto_smooth(angle=...)`, which appends a Smooth by Angle Geometry Nodes modifier, or `shade_smooth_by_angle` and `Mesh.set_sharp_from_angle`; read `corner_normals` | 4.1 |
| Principled `Specular`, `Emission`, `Transmission`, `Coat`, `Subsurface` | `Specular IOR Level`, `Emission Color` plus `Emission Strength`, `Transmission Weight`, `Coat Weight`, `Subsurface Weight` | 4.0 |
| `mod["Socket_2"] = value` on a Geometry Nodes modifier | `getattr(mod.properties.inputs, "Socket_2").value = value`, with the identifier looked up by name in `node_group.interface.items_tree` | 5.2 |
| `node_group.inputs.new(...)` | `node_group.interface.new_socket(name, in_out=..., socket_type=...)` | 4.0 |
| `scene.node_tree`, the Composite node, Glare `glare_type` | `scene.compositing_node_group` with a Group Output node; Glare options are input sockets, with `Type` set to `'Bloom'` | 5.0 |
| `material.use_nodes = True` | Unneeded, since new materials ship with a Principled BSDF and an output; deprecated for removal in 6.0 | 5.0 |
| Boolean `solver='FAST'` | `'FLOAT'` | 5.0 |
| `action.fcurves` | Channelbags through `bpy_extras.anim_utils` | 5.0 |
| `bpy.ops.x(context_dict)` | `with bpy.context.temp_override(...):` | 4.0 |
| `MeshEdge.crease`, `bm.edges.layers.crease` | The `crease_edge` attribute, for example `bm.edges.layers.float.new('crease_edge')` | 4.0 |
| `ShaderNodeTexMusgrave`, `export_scene.obj`, `import bgl` | Noise with `noise_type`; `wm.obj_export`; the `gpu` module | 4.x–5.0 |

A few more traps recur. Models invent node names such as `GeometryNodeCurveQuadrilateral`, `GeometryNodePackUVIslands` and `GeometryNodeSmoothByAngle`, which do not exist (the real ones are `GeometryNodeCurvePrimitiveQuadrilateral` and `GeometryNodeUVPackIslands`); Bool Tool, LoopTools and Extra Objects are no longer bundled; `view3d.view_all`, `render.opengl` and `screen.screenshot` fail headless; bmesh element indexing needs `ensure_lookup_table()`; and Blender 5.2 runs Python 3.13 ([headless 5.2.2 tests](../research_notes/Blender%20MCP%20game%20asset%20practices/bpy_techniques_blender5.md)). The fastest way to learn a dynamic enum is to assign an invalid string and read the TypeError, which lists every valid value, and every skill script should begin with `assert bpy.app.version >= (5, 2, 0)`, because the 5.2 Geometry Nodes input change does not fail the same way on 5.1. The operators-versus-data-API dispute also resolves cleanly. The Lab prompt prefers operators for standard one-off actions ([prompts.yml](https://projects.blender.org/lab/blender_mcp/src/branch/main/mcp/blmcp/data/prompts.yml)), while community packs prefer the data API because operators inside loops turn 50 ms jobs into 30-second ones and flood the undo stack ([TMHSDigital rule](https://github.com/TMHSDigital/Blender-Developer-Tools/blob/HEAD/rules/prefer-data-over-ops-in-loops.mdc)), and mesh operators at scale froze one user's Blender and lost work before a rebuild with `from_pydata` and instancing rendered 210 instances from 63 unique meshes ([staged scene construction](https://github.com/oh-ashen-one/blender-agent-skills/blob/HEAD/blender-staged-scene-construction/SKILL.md)). Use operators once, with explicit context and selection, and `bpy.data`, bmesh and instancing inside loops.

Materials stay shallow. Node-wired materials are where generated scripts most often fail to execute ([BlenderGym](https://arxiv.org/html/2504.01786v1)), and repeated scripted updates can stack duplicate output and BSDF nodes that render default grey until the tree is cleared and rebuilt ([#190](https://github.com/ahujasid/mcp-for-blender/issues/190)). Set inputs on the Principled node that every new 5.x material already contains, and mirror the color into `diffuse_color` so Workbench reviews match ([headless 5.2.2 tests](../research_notes/Blender%20MCP%20game%20asset%20practices/bpy_techniques_blender5.md)). Unwrap with `uv.smart_project`, whose angle is in radians (66° is 1.1519, with π/2 the maximum), followed by `uv.pack_islands`, and skip lightmap UVs in a Lumen project ([UV operators](https://docs.blender.org/api/5.1/bpy.ops.uv.html)). Bakes run in Cycles into the active image node of every material slot: selected-to-active normal bakes with explicit `cage_extrusion` and `max_ray_distance`, `normal_g='NEG_Y'` for Unreal's DirectX convention, every parameter passed explicitly because the scene's bake defaults differ from the operator's, and the high-poly hidden for self-bakes, since one visible occluder dropped mean AO from 1.0 to 0.576 ([bake operator](https://docs.blender.org/api/current/bpy.ops.object.html#bpy.ops.object.bake); [BakeSettings](https://docs.blender.org/api/5.1/bpy.types.BakeSettings.html); [headless 5.2.2 tests](../research_notes/Blender%20MCP%20game%20asset%20practices/bpy_techniques_blender5.md)). Cycles has no metallic bake pass, so metallic values travel through a temporary Emission shader ([Cycles baking](https://docs.blender.org/manual/en/latest/render/cycles/baking.html)). Bake after triangulating, so baker and engine share one tangent basis. The team's texture-set script baked a 512 px BC, N, ORM and E set in about 1.2 s on CPU ([local validation](../research_notes/Blender%20MCP%20game%20asset%20practices/local_validation.md)).

Procedural asteroids start from an icosphere at subdivision level 5 (5,120 triangles) with a broad CLOUDS displacement and a `VORONOI_F1` facet layer, voxel-remeshed for watertightness; the verified rock came out at 1,956 triangles with no non-manifold edges, and crystals are six-sided `create_cone` prisms with a poked tip ([headless 5.2.2 tests](../research_notes/Blender%20MCP%20game%20asset%20practices/bpy_techniques_blender5.md)). Choose density when generating rather than collapse-decimating noise. A Geometry Nodes scatter (Distribute Points on Faces, where Poisson mode uses `Density Max`, into Instance on Points with the distributed rotation and a Random Value scale, then Realize and Join) works through the 5.2 input API, but the modifier must be applied before export, or a 2,688-triangle scatter exports as two triangles ([kiln SKILL.md](https://github.com/elithril/blender-kiln/blob/HEAD/SKILL.md)).

AI-mesh cleanup is a fixed script rather than an improvisation. It imports the file (glTF, FBX or `wm.obj_import`), unparents and joins the parts, applies transforms, normalizes scene unit scale, rotates the front to the agreed axis, scales from world-space vertex extents to the brief, moves the pivot (bottom center for props, center for ships), merges by distance at about 0.5 mm after rescaling, dissolves degenerate faces, deletes loose geometry and floater islands below roughly 0.2–0.5% of the face count, recalculates normals, keeps a `_HIGH` copy as the bake source, reduces, unwraps, triangulates, rebakes, validates and exports. Generated assets often arrive at 0.01 object scale or with a non-unit scene scale, and Blender 5.x's glTF importer has no global scale option ([TMHSDigital rule](https://github.com/TMHSDigital/Blender-Developer-Tools/blob/HEAD/rules/validate-imported-mesh-scale.mdc)). Repair before reducing, then compare silhouette and shading afterwards ([Seele](https://www.seeles.ai/resources/blogs/ai-3d-model-cleanup-after-meshy-tripo-hunyuan)). Decimate keeps UVs and textures and suits rocks and Nanite statics; voxel remesh followed by QuadriFlow gives clean quads but discards every data layer, needs manifold input and forces a re-unwrap and rebake ([quadriflow_remesh](https://docs.blender.org/api/current/bpy.ops.object.html)), and remapping UVs after heavy decimation breaks the generator's texture alignment ([KatsBits](https://www.katsbits.com/codex/?p=9993)). On a simulated 20,480-triangle AI soup at 0.013 scale, the team's script welded 51,198 vertices, rescaled the mesh 64.7× to 180 cm, decimated it to 3,000 triangles and rebaked BC, N and ORM in about 3 s ([local validation](../research_notes/Blender%20MCP%20game%20asset%20practices/local_validation.md)); kiln repaired a 191,520-triangle TRELLIS mesh with 13,732 non-manifold edges to 9,000 triangles and none, on the official server ([blender-kiln](https://github.com/elithril/blender-kiln)).

## Unreal hand-off: one FBX per asset, calibrated once

Unreal is left-handed, Z-up, X-forward and measured in centimeters ([Epic coordinate system](https://dev.epicgames.com/documentation/en-us/unreal-engine/coordinate-system-and-spaces-in-unreal-engine)), while Blender should stay Metric at unit scale 1.0 so bevel widths, voxel sizes and bake cages all mean meters. Blender 5.2's exporter source shows what the scale modes do: the default All Local mode (`FBX_SCALE_NONE`) bakes the 100× meter-to-centimeter factor into root object transforms, whereas **`FBX_SCALE_UNITS` writes it into the file's unit header and leaves object and armature transforms at 1.0** ([export_fbx_bin.py](https://github.com/blender/blender/blob/blender-v5.2-release/scripts/addons_core/io_scene_fbx/export_fbx_bin.py)). EL4CTEO recommends FBX Units Scale precisely because the other mode produces a root bone scaled by 100 on skeletal imports ([EL4CTEO Unreal reference](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-export-pipelines/references/unreal.md)); arjun988's pack recommends FBX All instead ([arjun988 unreal-export](https://github.com/arjun988/blender-skills/blob/HEAD/.claude/skills/unreal-export/SKILL.md)), and Epic's Send to Unreal defaulted to All Local, which is fine for static meshes ([send2ue defaults](https://github.com/EpicGames/BlenderTools/blob/main/send2ue/resources/setting_templates/default.json)). The team's exporter used FBX Units Scale and round-tripped a 7.10 m ship with exact names, scale 1.0 and intact materials, rotating the authoring front (−Y) onto +X in the export copy; the Unreal side was not tested ([local validation](../research_notes/Blender%20MCP%20game%20asset%20practices/local_validation.md)). Epic documents no Interchange equivalent of the legacy importer's scene-conversion options ([Interchange reference](https://dev.epicgames.com/documentation/en-us/unreal-engine/interchange-import-reference-in-unreal-engine)), so the chain must be proved once per engine version with a calibration asset: a 1 m cube with a wedge on its nose, a `UCX_` hull and a `SOCKET_Nose` empty, accepted only when Unreal shows 100 cm bounds, actor scale 1.0, the wedge on the red X axis, the hull in collision view and the socket at X = 50.

```python
FBX_STATIC = dict(
    use_selection=True, object_types={'MESH', 'EMPTY'},
    global_scale=1.0, apply_unit_scale=True, apply_scale_options='FBX_SCALE_UNITS',
    axis_forward='-Z', axis_up='Y', use_space_transform=True, bake_space_transform=False,
    use_mesh_modifiers=True, mesh_smooth_type='FACE', use_triangles=True, use_tspace=True,
    add_leaf_bones=False, bake_anim=False, path_mode='AUTO', embed_textures=False)
# Skeletal: object_types={'ARMATURE', 'MESH'}, use_armature_deform_only=True, bake_anim as needed.
```

Each non-default value earns its place. Blender's own defaults (smoothing off, tangents off, leaf bones on, animation baking on) rarely suit a game exporter ([io_scene_fbx source](https://github.com/blender/blender/blob/blender-v5.2-release/scripts/addons_core/io_scene_fbx/__init__.py)); Face smoothing still writes the custom normals while silencing Unreal's missing-smoothing-group warning ([UE forum](https://forums.unrealengine.com/t/solved-no-smoothing-group-information-was-found-in-this-fbx-scene-really-important/152360)); tangents export only from triangle and quad meshes ([EL4CTEO export pipelines](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-export-pipelines/SKILL.md)); and Apply Transform (`bake_space_transform`) is flagged experimental and broken with armatures. Either axis pair works (−Z/Y as above, or Send to Unreal's Y/Z with scene conversion off), but mixing them does not. FBX is the format for authored assets, because Epic documents its `UCX_`, `SOCKET_` and LOD conventions only for FBX ([FBX static mesh pipeline](https://dev.epicgames.com/documentation/en-us/unreal-engine/fbx-static-mesh-pipeline-in-unreal-engine)); glTF suits generator props, but it uses OpenGL normals and Interchange keeps no legacy glTF importer to fall back on ([UE forum](https://forums.unrealengine.com/t/fbx-import-changed/2144275)).

Names are contracts with the importer. Epic's prefixes are `SM_`, `SK_`, `SKEL_`, `PHYS_`, `M_`, `MI_` and `T_` ([Epic naming](https://dev.epicgames.com/documentation/en-us/unreal-engine/recommended-asset-naming-conventions-in-unreal-engine-projects)). Custom collision is `UCX_<RenderMeshName>_##` (or `UBX_`, `USP_`, `UCP_`) and must match the final object name exactly; when a file holds several meshes with custom collision only the first mesh's collision imports, and a file with `SOCKET_` empties may hold only one render mesh ([FBX static mesh pipeline](https://dev.epicgames.com/documentation/en-us/unreal-engine/fbx-static-mesh-pipeline-in-unreal-engine)). Hence one render mesh per FBX, exported from an export copy moved to the world origin with its collision and socket children, the pattern the team's exporter verified with automatic convex hulls built from at most 64 support points ([local validation](../research_notes/Blender%20MCP%20game%20asset%20practices/local_validation.md)). Hulls should be closed, non-overlapping, under 255 vertices and slightly smaller than the visible mesh to reduce snagging ([EL4CTEO Unreal reference](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-export-pipelines/references/unreal.md); [collision-proxy](https://github.com/arjun988/blender-skills/blob/HEAD/.claude/skills/collision-proxy/SKILL.md)), and Send to Unreal's automatic prefixing breaks custom collision for exactly this name-matching reason ([poly-hammer #187](https://github.com/poly-hammer/BlenderTools/issues/187)). Pivots follow use: ships and projectiles at the center of mass with the nose on +X, props at bottom center, kit pieces at a floor corner on exact 100 cm multiples.

| Map | Blender side | UE sRGB | UE compression | Notes |
|---|---|---|---|---|
| `T_<Asset>_BC` base color | DIFFUSE color bake, or the emission route for metallic surfaces; sRGB PNG | On | Default or BC7 | No lighting baked in |
| `T_<Asset>_N` normal | Tangent-space NORMAL bake with `normal_g='NEG_Y'`, Non-Color | Off | Normalmap (BC5) | Or flip green in Unreal, never both |
| `T_<Asset>_ORM` | R = ambient occlusion, G = roughness, B = metallic, Non-Color | Off | Masks | Same channel order glTF uses |
| `T_<Asset>_E` emissive | EMIT bake, sRGB | On | Default or BC7 | Multiplied by an emissive-strength parameter in the material instance |

Blender bakes OpenGL normals with green pointing up by default ([Normal Map node](https://docs.blender.org/manual/en/latest/render/shader_nodes/displacement/normal_map.html)) while Unreal expects the DirectX convention, which is why the green flip must happen exactly once ([UE forum](https://forums.unrealengine.com/t/normal-map-directx-or-is-it/2664394)); Interchange can detect normal maps and flip green on import ([Interchange reference](https://dev.epicgames.com/documentation/en-us/unreal-engine/interchange-import-reference-in-unreal-engine)). Keep sizes power-of-two, because only those textures stream ([Texture Asset Editor](https://dev.epicgames.com/documentation/en-us/unreal-engine/texture-asset-editor-in-unreal-engine)). Texture memory runs about 5.3 MB at 1K, 21 MB at 2K and 85 MB at 4K, ORM packing cuts grayscale maps threefold, and UV seams and hard edges duplicate vertices so that engine vertex counts run 1.5–3× Blender's ([game optimization](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-game-optimization/SKILL.md)).

On the Unreal side, Interchange has been the default FBX importer since 5.5, with the legacy importer reachable through `Interchange.FeatureFlags.Import.FBX=False` ([UE forum](https://forums.unrealengine.com/t/fbx-import-changed/2144275)). In 5.7, FBX materials always import as Material Instances of a Phong-based parent even when standalone materials are requested, and an Epic developer said the fix missed 5.7 ([UE forum](https://forums.unrealengine.com/t/5-7-preview-fbx-materials-getting-imported-as-instances-instead-of-standalone-materials/2664714)), so the team should build its own master materials and assign instances of them rather than fight the importer. Import at final size, because distance-field resolution follows imported scale; keep walls at least 10 cm thick and walls, floors and ceilings as separate meshes; enable mesh distance fields for software Lumen ([Lumen technical details](https://dev.epicgames.com/documentation/en-us/unreal-engine/lumen-technical-details-in-unreal-engine)); and switch off Generate Lightmap UVs, which only adds import time and data in a project that bakes no lightmaps ([Epic Nanite](https://dev.epicgames.com/documentation/en-us/unreal-engine/nanite-virtualized-geometry-in-unreal-engine)). Nanite takes opaque and masked static and skeletal meshes but not translucency, morph targets or forward rendering, limits world-position offset ([Epic Nanite](https://dev.epicgames.com/documentation/en-us/unreal-engine/nanite-virtualized-geometry-in-unreal-engine)), and community reports cap it at 64 material sections ([UE forum](https://forums.unrealengine.com/t/nanite-should-validate-that-mesh-has-64-or-fewer-materials-rather-than-crashing/2430076)). UE 5.9 Preview advertises order-independent transparency for Nanite translucency that the Nanite page still denies ([UE 5.9 release notes](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-5-9-release-notes)), so canopies, shields and energy blades stay on separate non-Nanite meshes. Emissive values above 1.0 drive bloom, small emitters need Emissive Light Source to light consistently under Lumen, and bloom is tuned in a Post Process Volume rather than by lowering emissive values ([Epic emissive](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-the-emissive-material-input-in-unreal-engine)).

Skeletal crew need extra care. Export with leaf bones off and deform bones only; an armature object named exactly Armature is dropped on import so its first bone becomes the root; and FBX remains the battle-tested skeletal path ([EL4CTEO Unreal reference](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-export-pipelines/references/unreal.md)), especially after a UE 5.8 report of skinned glTF files splitting into several skeletal meshes ([UE forum](https://forums.unrealengine.com/t/ue-5-8-gltf-skinned-gltf-splits-into-several-skeletal-meshes-the-shipped-gltf-pipeline-preset-ships-do-not-combine-regression-from-5-7/2740512)). Automatic weights fail on generated meshes made of many disconnected islands ([rigging guide](https://github.com/ahujasid/mcp-for-blender/blob/HEAD/src/blender_mcp/guides/rigging.md)), and kiln measures vertices per deform bone before choosing a rig, finding automatic weights useless below about 20 ([kiln SKILL.md](https://github.com/elithril/blender-kiln/blob/HEAD/SKILL.md)); importing a vendor-rigged FBX straight into Unreal and retargeting there avoids the Blender round trip entirely.

Automate the import with Unreal Python rather than Send to Unreal. Epic's last Send to Unreal release is 2.4.3 from November 2023 ([EpicGames/BlenderTools](https://github.com/EpicGames/BlenderTools)), and the community fork is tested only on Blender 3.6 and 4.2 with UE 5.3 and 5.4, depends on the legacy importer and has open Blender 5.x blockers ([poly-hammer releases](https://github.com/poly-hammer/BlenderTools/releases); [poly-hammer #193](https://github.com/poly-hammer/BlenderTools/issues/193)); xavier150's Blender for Unreal Engine add-on, at v4.4.8 from July 2026, is the maintained GUI alternative ([BfU](https://github.com/xavier150/Blender-For-UnrealEngine-Addons)). The scripted path calls `InterchangeManager.get_interchange_manager_scripted().import_asset(...)` with `ImportAssetParameters` set to `is_automated=True` and a saved pipeline asset in `override_pipelines` ([ImportAssetParameters](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/ImportAssetParameters?application_version=5.7); [UE forum example](https://forums.unrealengine.com/t/python-or-blueprint-example-for-importing-obj-file-in-ue5-1-interchange-import-pipeline/714987)), then fixes each mesh with `StaticMeshEditorSubsystem` methods such as `set_nanite_settings`, `add_simple_collisions`, `set_convex_decomposition_collisions`, `set_lod_group` and `set_generate_lightmap_uv` ([StaticMeshEditorSubsystem](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/StaticMeshEditorSubsystem?application_version=5.7)), plus texture compression and sRGB fix-ups. Probe pipeline property names with `dir()`, since several are undocumented, and confirm the default pipeline asset paths, which come from a UE 5.1-era post. In this environment the flopperam Unreal MCP's `python_execution` tool can run those scripts ([flopperam](https://github.com/flopperam/unreal-engine-mcp)); UE 5.9's experimental built-in Unreal MCP adds an `ImportFile` tool for static and skeletal meshes, but its replace and save flags default to false, and new projects expose no level-editing tools until Toolset plugins are enabled ([Unreal MCP](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-mcp-in-unreal-editor); [MegaJam preview](https://forums.unrealengine.com/t/unreal-engine-5-9-megajam-preview/2852840)). For meshes that skip Nanite, halving triangles per LOD with switches near screen sizes 0.5, 0.25 and 0.125 is a sound default ([game optimization](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-game-optimization/SKILL.md)); whether Blender's FBX exporter writes LOD groups Unreal recognizes is unverified, so rely on Unreal's automatic LODs or on Nanite.

## Package one skill set for Claude Code, Codex and Cursor

No single directory reaches every agent natively. Claude Code reads `.claude/skills/<name>/SKILL.md` and explicitly ignores anything under `.agents/` ([Claude Code skills](https://code.claude.com/docs/en/skills); [Claude Code memory](https://code.claude.com/docs/en/memory)), and the request to change that was still open on November 12 ([#107421](https://github.com/anthropics/claude-code/issues/107421)). Codex documents only `.agents/skills` for repositories and has no setting for extra skill roots ([Codex skills](https://learn.chatgpt.com/docs/build-skills); [Codex config schema](https://github.com/openai/codex/blob/main/codex-rs/core/config.schema.json)); Cursor reads `.agents/skills` and `.cursor/skills` plus, for compatibility, `.claude/skills` and `.codex/skills` ([Cursor skills](https://cursor.com/docs/context/skills)); Copilot reads `.github/skills`, `.claude/skills` and `.agents/skills` ([GitHub agent skills](https://docs.github.com/en/copilot/concepts/agents/about-agent-skills)). The robust Windows layout is therefore **a canonical `.claude/skills/` tree plus a generated, gitignored `.agents/skills/` copy that a sync script produces for Codex users**, which is exactly what OpenAI's own Claude-to-Codex migrator does with real file copies ([migrate-to-codex](https://github.com/openai/skills/blob/main/skills/.curated/migrate-to-codex/references/differences.md)), with a short skills index in AGENTS.md as a fallback pointer. Gitignoring the copy keeps Cursor from listing every skill twice. Committed symlinks are the fragile option, because Git for Windows checks them out as small text files unless Developer Mode and `core.symlinks=true` are set before cloning ([Git for Windows](https://gitforwindows.org/symbolic-links)). Add a `.gitattributes` rule forcing `eol=lf` for skill files, since Claude Code fixed a CRLF bug in multi-line shell blocks only in an autumn 2026 release ([Claude Code changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)).

Write to the open Agent Skills specification, which Anthropic donated to the Linux Foundation's Agentic AI Foundation on October 22, 2026, citing more than 70 integrating platforms ([Anthropic](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation)). Portable frontmatter uses only `name`, `description`, `license`, `compatibility`, `metadata` and `allowed-tools`. The `name` matches the folder, runs to at most 64 lowercase letters, digits and hyphens, and avoids the words claude and anthropic; the `description` stays under 1,024 characters, opens with a third-person statement of what the skill does, adds a use-when clause naming the triggers, and is quoted or folded whenever it contains a colon, the most common cross-client YAML failure ([Agent Skills spec](https://agentskills.io/specification); [authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices); [client implementation guide](https://agentskills.io/client-implementation/adding-skills-support)). Claude Code-only keys such as `disable-model-invocation` are safe locally, because other agents ignore unknown keys, but uploads to claude.ai reject them. Keep each `SKILL.md` under 500 lines with references one level deep, and put the Gotchas first: after auto-compaction Claude Code re-attaches only the first 5,000 tokens of each invoked skill, within 25,000 tokens in total ([Claude Code skills](https://code.claude.com/docs/en/skills)). Prefer defaults to menus, procedures to single answers, and a bundled script wherever agents keep rewriting the same logic ([skill-creator best practices](https://agentskills.io/skill-creation/best-practices)).

```yaml
---
name: blender-unreal-export
description: >
  Validates and exports finished Blender 5.2 assets to Unreal Engine 5 as one FBX per asset
  with cm scale, +X forward, UCX_ collision and SOCKET_ sockets. Use when an asset is finished,
  or when someone asks to export, send or get a model into Unreal, even without naming FBX.
compatibility: Blender 5.2.2 with the Blender Lab MCP add-on 1.0.3, or blender.exe for headless runs.
---
```

Skills should reference tools by server and bare name (the Blender Lab MCP server under the key `Blender`, with tools such as `execute_blender_code` and `get_objects_summary`), give Claude Code's callable form `mcp__Blender__<tool>` as the example, and tell other agents to match on the tool-name suffix ([Claude Code MCP](https://code.claude.com/docs/en/mcp); [authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)). Pre-approve only read-only tools in `allowed-tools`, which Claude Code applies to the invoking turn alone and Codex treats as guidance rather than a permission boundary, and never `execute_blender_code`, which runs unsandboxed Python ([Claude Code skills](https://code.claude.com/docs/en/skills); [migrate-to-codex](https://github.com/openai/skills/blob/main/skills/.curated/migrate-to-codex/references/differences.md)). Every Blender skill opens with a Step 0 modeled on OpenAI's official skills: a cheap read-only call confirms Blender is live; if no Blender tool exists or the call errors, the agent explains how to start Blender with the add-on and falls back to headless Blender; if Blender is unavailable entirely, it emits the script and manual steps; and it always reports which path ran ([openai-docs skill](https://github.com/openai/skills/blob/main/skills/.curated/openai-docs/SKILL.md); [linear skill](https://github.com/openai/skills/blob/main/skills/.curated/linear/SKILL.md)). Codex can also declare the MCP dependency in `agents/openai.yaml` and offer to install it, although support for a local stdio server is unverified ([Codex skills](https://learn.chatgpt.com/docs/build-skills)).

One script per operation serves both execution paths. Each exposes `main(**kwargs) -> dict` for the live path and an `if __name__ == "__main__":` block that parses arguments after `--` and writes JSON for the headless path. The agent sends only a short loader through `execute_blender_code`, which avoids paying for the code twice, once when read and again as tool input; the headless form adds `--factory-startup`, `--python-exit-code 1` (without which a failed export still exits 0, per [kiln](https://github.com/elithril/blender-kiln/blob/HEAD/SKILL.md)) and empty stdin.

```python
# Live path, sent through execute_blender_code
import runpy
ns = runpy.run_path(r"C:/repo/.claude/skills/blender-mcp/scripts/asset_report.py")
result = ns["main"](collection="SM_Ship_Hero_Vanguard", tri_budget=60000)
```

```bash
# Headless path from Git Bash, same script
"/c/Program Files/Blender Foundation/Blender 5.2/blender.exe" --background --factory-startup \
  checkpoints/ship_v03.blend --python-exit-code 1 \
  --python .claude/skills/blender-mcp/scripts/asset_report.py -- --out out/report.json < /dev/null
```

Scripts pass absolute paths into Blender, whose working directory is not the skill folder; never prompt; stay idempotent with a dry-run option; and keep output size predictable, because harnesses truncate around 10,000–30,000 characters ([Using scripts](https://agentskills.io/skill-creation/using-scripts)). Helper processes on Windows spawn windowless with `CREATE_NO_WINDOW` ([ai-skills-blender AGENTS.md](https://github.com/SamuelAsherRivello/ai-skills-blender/blob/HEAD/AGENTS.md)). The repository's current skill set already follows the split this research supports; what each skill should own, and the scripts the team validated headless on 5.2.2 ([local validation](../research_notes/Blender%20MCP%20game%20asset%20practices/local_validation.md)), are summarized below.

| Skill | Owns | Bundled scripts |
|---|---|---|
| `blender-mcp` (read first) | Step 0 and the fallback ladder, tool map, per-call template, Windows traps, the 5.2 API-drift table, safety and confirmation rules, the hard-gate audit and contact sheet | `asset_report.py`, `assembly_check.py`, `review_renders.py` |
| `blender-game-asset` | Brief template, palette roles, concept handling, asset routing, the stage ladder, human gates, fresh-reviewer rounds and stop rule; hard-surface stack, component library and procedural environment recipes | `hardsurface.py`, `procedural_rocks.py` |
| `blender-ai-mesh-cleanup` | Generator settings, import and repair order, reduction choice, rebake, provenance and licence log | `cleanup_ai_mesh.py` |
| `blender-texturing` | Material and UV rules, the Unreal texture set, color spaces, metallic through emission, bake-after-triangulate | `bake_texture_set.py` |
| `blender-unreal-export` | FBX settings, naming, collision and sockets, calibration asset, round-trip check, Unreal Interchange import and post-fix | `export_for_unreal.py`; the Unreal-side import script is untested |

Borrow content rather than whole packs. EL4CTEO's Blender 5.2 router with a mandatory QA gate, kiln's numbered rules each tied to a measured incident together with its official-server mapping, SamuelAsherRivello's skills written for the official Lab MCP on Windows, RobLe3's dual-backend notes and TMHSDigital's wrong-versus-right 5.x API rules are the strongest sources ([blender-core](https://github.com/EL4CTEO/blender-skills/blob/HEAD/skills/blender-core/SKILL.md); [kiln SKILL.md](https://github.com/elithril/blender-kiln/blob/HEAD/SKILL.md); [ai-skills-blender](https://github.com/SamuelAsherRivello/ai-skills-blender/blob/HEAD/skills/blender-create-model/SKILL.md); [cc-blender-skill backends](https://github.com/RobLe3/cc-blender-skill/blob/main/plugin/skills/text-to-blender/references/mcp-backends.md); [TMHSDigital rules](https://github.com/TMHSDigital/Blender-Developer-Tools/tree/HEAD/rules)). Popular packs still carry stale API, such as the `BLENDER_EEVEE_NEXT` id in one RobLe3 recipe ([blender-pro-workflow](https://github.com/RobLe3/cc-blender-skill/blob/HEAD/plugin/skills/blender-pro-workflow/SKILL.md)), so nothing is copied without a 5.2 check. Before writing long documentation, build at least three evaluations and a no-skill baseline, tune each description against about 20 should-trigger and near-miss prompts run three times each, and test with every model the team uses ([authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices); [optimizing descriptions](https://agentskills.io/skill-creation/optimizing-descriptions)). Finally, encode the Lab's own norms as rules (inspect before mutating, never assume missing values, confirm destructive changes, report what changed) ([prompts.yml](https://projects.blender.org/lab/blender_mcp/src/branch/main/mcp/blmcp/data/prompts.yml)), and never let an agent file upstream issues or pull requests, which Blender's AI contribution policy rejects ([Blender AI policy](https://developer.blender.org/docs/handbook/contributing/ai_contributions/)).

## Conclusion

The center of gravity in agent-driven asset work has moved. Getting bpy to run is close to solved, since retries, doc lookup and coding harnesses push executability near 0.97, so skills that mainly teach Blender's API hit diminishing returns once the 5.2 drift table is in place. The scarce resources are design judgment and trustworthy verification, which is why the most valuable skills encode decisions (routing, briefs, budgets, thresholds) and deterministic checks, and rank the agent's own visual opinion last. The official server's minimalism and its Windows bugs, which look like weaknesses, push toward the right architecture: scripts as the source of truth, runnable live or headless, identical across Claude Code, Codex and Cursor, and doubling as validators before anything reaches Unreal.

Two implications follow for the jam. Nanite and Unreal's material stack move much of the quality budget for static assets away from Blender topology craft and toward silhouette, materials and lighting, where a human art director and Unreal look development outrank more modeling code and where decimated generator output becomes acceptable. And the first day's deliverable is infrastructure rather than art: a calibrated FBX round trip, a component library and a review harness turn every later asset into a predictable trip through the gates, while skipping them turns four days into a series of one-off fixes.
